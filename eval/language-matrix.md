# 语言评估矩阵

本矩阵对应 `docs/product-evaluation.md` 的语言覆盖要求。机器可读索引在 `coverage.json` 的 `languages`，实际结果由 `scripts/collect_local_results.py` 从 Go JSON 输出核对。每个语言行分别检查语言事实、已关联的共用规则和原生框架；任一部分缺失、失败或跳过，该行不能记为通过。

## 证据怎样组合

语言层从固定源码提取声明、引用、用法、入口、风险和测试事实。共用检查层使用这些事实执行 D、T、V、S 规则，规则对应的提示、放行、例外与单次拦截边界见 `coverage.json` 的 `rules`。语言资料包再核对从任务、修改到反馈的连接。动态部分单独运行真实工具，检查用例选择、覆盖、有效变异和工作区隔离，不从语法解析结果推断运行成功。

普通测试中缺少可选工具而跳过的结果仍保留在报告里；原生列只读取 `--native-logs` 指定的执行证据。固定源码、原生框架、原生 Agent 与目标平台是不同验证范围，本矩阵只汇总前两类。

| 范围 | 语言事实与边界 | 原生验证 |
| --- | --- | --- |
| Go | 接口候选、泛型推断、错误、字段值、入口、风险、子测试与断言 | Go 用例选择、覆盖与变异、反向测试导入范围 |
| Python | ABC、Protocol、异常、默认值、外部字段、入口、风险、pytest 与 unittest 身份 | pytest 执行 unittest 和参数用例、覆盖、失败分类、工具恢复及依赖范围 |
| TypeScript | 接口与抽象类、泛型、导出、字段和调用、TSX 入口、测试身份 | Vitest 逐例选择、覆盖与变异、动态名字整体保留及相关测试范围 |
| JavaScript | 导出、调用和字段、入口、风险、Jest 与 Vitest 断言规则 | Jest 逐例选择、覆盖与变异、动态名字整体保留及相关测试范围；Vitest 结果另见其对应执行 |
| Java | 接口与匿名实现、泛型、异常、可见性、注解入口、字段和 JUnit 身份 | Maven、Gradle、JUnit、JaCoCo，失败分类与反向模块依赖范围 |
| Rust | trait、泛型、错误、字段、属性与 builder 入口、宏未知、测试身份 | 普通 test、tokio::test、rstest、cargo-llvm-cov 与 workspace 依赖范围 |
| C# | 通用声明、接口候选、字段值、转发、直接依赖及未知能力 | 不提供专用测试 Runner |
| Ruby | 通用声明、默认值、命名参数、实例字段、转发与直接依赖 | 不提供专用测试 Runner |
| PHP | 通用声明、命名参数、属性、接口候选、转发与直接依赖 | 不提供专用测试 Runner |
| 文档 | 文件归属、变化、方案范围及排除规则 | 不进行代码用法或动态测试 |
| 配置 | 文件归属、变化、方案范围及测试数据分类 | 不由配置文本推断运行行为 |
| 依赖清单 | 文档列出的直接依赖、锁文件关联、版本更新和无法解析的范围 | 不把锁文件或间接依赖单独算作新增行为 |

## 结果边界

180 个语言事实测试引用包含共用测试复用，不表示新增了 180 个测试，也不表示逐条枚举了所有语言与规则的笛卡尔积。通用规则的前提由共用回归核对，语言差异由对应事实断言核对；测试入口和来源都保留在结果中。

未定义的语法、无法核对的动态调用、宏、间接写入、默认值及运行时名字保持具体的未知反馈。C#、Ruby、PHP 不补专用入口、风险或测试规则；D7 在这些语言只使用通用旧名转发事实。API 框架的固定源码识别不等于已在所有库版本中原生运行。各次原生结果只适用于其记录的平台、版本和依赖，不替代 Windows、Linux、WSL 或真实 Agent 的验收。
