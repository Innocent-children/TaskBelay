# TaskBelay for Codex

This source adapter uses the current local engineering Core: authorized goals, actual changes, real execution evidence, cumulative cost and recovery. Published versions and stable support records are unchanged; build this checkout for the new contract. Old data is preserved and unsupported, so select a separate explicit TASKBELAY_DATA_DIR.

Install the public manager with npm install -g taskbelay@latest and taskbelay install --host codex. For current source use node scripts/taskbelay-local.mjs install --host codex --yes from the repository. Node.js >=24 is required; source builds additionally need Go >=1.26 and pnpm >=11 <12.

Reload the Codex plugin and inspect/trust its apply_patch hook with /hooks.

Invoke the TaskBelay Skill and state the desired outcome and limits. First show the understanding and complete plan and obtain explicit user confirmation; ordinary follow-ups retain that approval, while material revisions require a new confirmation. Alternate coding and verification, retain semantic basis/uncertainty and use Core run_check for actual local results. Unsupported shell/remote operations must be described honestly. Resume a saved Task in its bound workspace and read the original run after a lost response.

The hook covers apply_patch paths; other changes are observed at checkpoints. Core cannot authenticate conversation or prove semantic judgments. Checks still follow native Host permissions.

Status/doctor/upgrade/uninstall use the unified manager with --host codex; ordinary removal retains Task data. Optional workspace preparation reuses actual authorization_ref and yields current repositories. Relocation is unsupported. Done/cancelled does not authorize Git, publication or cleanup.
