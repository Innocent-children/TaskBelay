# 过度测试判定

验证是否多余，取决于它能否回答尚未解决的问题，以及是否存在成本更低、证据同样适用的操作。测试数量、覆盖行数、连续运行次数不能直接作出判断。保留一条测试与本次是否运行它，是两个独立决定。

本文定义新算法。证据版本、依赖失效、未知处理和预算由 [算法设计](algorithm.md) 定义。当前程序的 T1 至 T6、V1 至 V3、风险数量建议和按语言运行的流程属于旧实现；不得把其历史报告当成新算法的结果。

## 明确待验证问题

从当前需求、直接相关的既有行为、实际改动及已发现问题中提取待验证问题。每个问题描述前提、动作、可观察结果和适用环境，例如“输出目录不可写时，导出失败且保留原文件”。

问题必须有来源，不因“改了代码”自动增加测试目标。静态阅读、已有有效观察和直接推演可以回答的问题，不强制转换为新测试。模型提出的风险只作为候选；没有当前依据的故障假设、未来扩展和平台矩阵不能自动扩大任务。

同一来源的证据只计一次。代码行覆盖表示执行过某些位置，变异结果表示某些改动被检测到；它们都不能直接证明某项业务断言成立。命令退出成功只说明相应执行结果，结果能否回答该问题，还要核对输出约定。

以 U 表示尚未回答的问题集合。既有证据只有在来源、内容、依赖、环境和适用范围仍有效时，才能从 U 中移除对应问题；证据过期后，对应问题重新加入 U。

## 选择验证操作

候选操作可以是阅读差异、静态分析、运行已有用例、构建或一次必要的临时测试。每个操作 aⱼ 记录：

- 可检查的问题集合 Sⱼ，以及这种对应关系的依据；
- 实际输入范围、环境、前置准备和输出约定；
- 正的执行成本 cⱼ，包括已知的启动、准备与执行成本；
- 授权、是否有副作用、能否独立执行及不确定项。

Sⱼ 表示操作具备检查能力，不保证运行成功，也不保证结果足以回答所有问题。成本未知时保留估计范围和来源，不用零成本参与排序。没有候选能检查的问题保留为未知，不靠无限生成测试补齐。

在候选覆盖关系固定、成本独立且可加的选择阶段，求解加权集合覆盖：

```text
min Σ cⱼ yⱼ
subject to 对每个 u∈U，Σ[u∈Sⱼ] yⱼ ≥ 1
yⱼ∈{0,1}
```

使用贪心近似，每次选取“新增覆盖的问题数 / 成本”最大的操作，直到覆盖所有能够检查的问题。比值相同时按固定规则选择，使同一输入得到可复现的结果。如果一个候选能检查的问题都包含在另一个操作中，成本又不低，且两者前提和输出能力相同，就可以排除该候选。不能仅凭执行行数作出这一判断。

以问题到操作的反向索引更新新增覆盖数，用可更新优先队列维护比值。设操作数 t、问题数 r、覆盖关联总数 L=Σ|Sⱼ|，一次固定选择阶段时间为 `O((L+t) log t)`，空间为 `O(L+t+r)`；确定操作与问题的覆盖关系、估计成本所需的开销另计。每个关联只在该问题首次被计划覆盖时更新。

在覆盖关系准确固定、全部问题可覆盖、操作成本为正且独立可加的条件下，成本不超过最优解的 Hᵣ 倍，且 Hᵣ≤1+ln r。U 为空时直接停止，不使用该公式；队列实现以 log(max(2,t)) 处理空集和单元素。该界只适用于这个集合覆盖模型，不等于实际测试效果保证。

### 根据执行结果调整计划

选择得到的是计划。执行一个操作后，按真实结果更新证据与 U，再决定是否继续。断言失败转入相关问题诊断；启动失败、输出缺失或无法解释的结果保留未知。不能因为计划里覆盖了所有问题就宣称验证完成。

例如 U={正常输出、失败后保留原文件、输入格式校验}。操作 A 检查前两项，成本 2；B 检查格式校验，成本 1；C 检查全部，成本 8。在覆盖与成本假设成立时选 A+B；如果 A 的结果只能确认正常输出，保留原文件这一项仍未解决，不能直接结束。

操作共用昂贵准备步骤、存在执行顺序或共享状态时，先表达为带前提的操作组或有约束调度问题。不得重复计算准备费用，也不得套用独立集合覆盖的近似界。不能独立运行的操作默认串行；并行必须有已核对的独立条件。

## 证据复用与失效条件

验证记录使用以下标识判断是否可以复用：

```text
K = H(操作标识, 完整输入清单, 必要环境, 输出约定)
```

操作标识包含实际程序、参数、目录、选择范围及必要工具版本。输入清单不仅包括文件内容，还包括目录枚举、缺失文件等否定依赖、配置、工具及外部状态的相关版本。只记录“实际读过的文件”不足以证明输入完整：新增插件或此前不存在的可选配置也可能改变结果。

共享证据图记录输入到观察、观察到问题的关系。变更沿可能依赖图传播，局部证据不因无关文件变化全部失效；依赖范围不完整时扩大核对范围或标为未知，不能据此获得缓存命中。整体工作区 tree 相等既不是局部复用的必要条件，也不能替代外部环境一致性。

静态计算可复用同输入下的确定结果，包括仍然未知的结果，但必须保留未知及原因。执行错误、超时或取消不能缓存成有效的业务证据，也不能跳过较新的异常记录去复用旧的成功结果。修复相关能力、输入变更或明确刷新时重新安排相关检查。

## 重复验证的判定

仅在以下条件全部成立时，才把本次操作认作已完成的确定性重复验证：

1. 上次已实际完成，结果可核对且满足同一输出约定；不是正在运行、失败、中断或未知。
2. 操作标识、完整输入清单、必要环境及相关依赖均相同且仍有效。
3. 有依据认为操作在这些条件下是确定性的；没有新的诊断问题或采样目的。
4. 没有明确的重跑要求；没有必须再次产生的副作用或缺失的构建产物。

满足条件后按产品规则最多拦一次，提供可复用结果与依据。混合 shell 命令含有其他必要操作时，不能拦掉整条命令。输入、退出状态或环境不可核对时只提示，不拒绝运行。用户已经明确要求重跑，记录有效范围后执行，不再次索要同一授权。

运行范围过大只在存在能回答同一组待验证问题、前提成立且成本较低的具体替代时提示。不因为“全量测试”名称或第七次运行直接裁定；未知输入的命令照常执行并记录可取得的信息。

## 测试用例的保留与精简

本次选择没有运行某用例，不表示它应从项目删除。保留测试需要核对它守住的行为、断言、执行条件、维护价值及用户保留要求。

只有具体替代覆盖相同的已核对行为和条件时，才提出合并或精简建议。相同行覆盖、相同变异发现集合、相近文本或较多 mock 都只提供候选线索。对复杂边界、独立回归问题和不同断言，不能用集合相似度消除。

历史测试不得因为当前任务没有涉及就自动删除，也不能把旧断言自动升级为当前需求。TaskBelay 不设统一的建议用例上限，不通过风险加分计算“应该写几条”。有效结果可以是无需新测试、复用现有证据、执行一个操作或仍需进一步信息，必须分别说明依据。

## 变异测试与非确定性问题

动态检查默认关闭，仅按设置或明确请求执行。TaskBelay 主动执行时从固定快照导出临时副本，使用项目已经存在的运行入口；Agent 日常命令仍按原工作目录执行。环境、准备、副作用与可并行条件遵循 [分析输入与验证执行](languages.md)，不按开发语言选择算法。

变异测试只用于调查明确的问题。先确定要回答的问题和有限的变异范围，确认基线及执行对象，再运行必要的变异；编译失败、环境错误、超时和无效变异不能计为发现缺陷。按独立问题或候选组保留已完成证据，不因后续预算到期抹去有效局部结果，也不把局部样本写成全量结论。

确需判断非确定性失败时，重复样本不是确定性重复验证。可采用顺序似然比检验：事先明确失败率假设 p₀<p₁、错误容忍 α、β 和采样上限；对独立且条件固定的观测累积对数似然比，在证据达到阈值时停止，否则到预算时报告未定。阈值和实际错误界必须按所用检验的前提核对，不能宣称任意相关样本都满足同一保证。

该方法只服务于明确的稳定性问题，不自动创建可靠性测试任务；不能把选择性重跑、环境变化或相关结果当作独立样本，也不能用“连续通过若干次”证明没有缺陷。它不决定普通开发需要几次验证。

## 停止条件与结果报告

当前待验证问题全部有有效证据回答后，停止验证；没有可行且获授权的操作、预算耗尽或缺少必要信息时，停止并报告未完成范围。任务可以按产品流程结束，但检查未知仍保留，不改写成验收通过。

每项建议列出问题、候选操作、成本依据、已复用证据、实际结果和未知条件。将执行次数与重复拦截次数分开；总成本包括 TaskBelay 自己的分析和命令，不能靠减少 Agent 命令数掩盖新增开销。计划、运行中、已完成、复用和未执行分别记录。
