# 过度测试判定

过度测试有两种：测试代码中守不住独有行为的用例，以及不提供新信息的验证运行。前者用等价类和变异结果判断，后者用验证输入记录判断。保留一条测试和本次是否运行它，是两个独立的决定。

本文定义目标算法。验收依据、分组检验、合并信号和问题身份见 [算法核心](algorithm.md)，测试内容的识别、命令记录和副本运行见 [输入与执行协议](languages.md)。当前程序的 T1 至 T6、V1 至 V3 和风险数量建议属于现有实现，历史报告按生成它的版本解释。

## 1. 用例与表格行

测试单元按 [输入与执行协议](languages.md) 学到的测试内容识别。一条可以单独运行的测试是一条用例。表格测试的每一行，是同一个列表字面量中骨架相同的元素：把元素的词序列规整（字面量换成类别）后哈希相同。

只有本次新增、且全部来自 Agent 编辑的用例可以成为删除或合并候选。以下用例预先放入**保留集合**：起点已有的用例、作为验收依据的用例、用户点名的用例，以及含工作区更新的用例。

## 2. 等价类与边界值

被测单元中与比较运算符（`<`、`<=`、`==`、`!=`、`>`、`>=`）相邻的常量，是这段代码真正区分输入的分段点。数值常量把输入分成区间，字符串常量把输入分成“等于某个常量”和“都不等于”。被测单元由用例引用的新词和名字确定。

把每条用例、每一行的输入字面量映射到所属区间，并标出它是否正好落在某个分段点 c 或 c±1 上、是否等于某个字符串常量：

- **重复候选**：同一被测单元、同一等价类、断言形状相同的用例或行。
- **测试预算**：等价类数加边界点数。新增用例超过预算时，展示超出的部分及其等价类；预算不是上限，超出的部分只是复核对象。

排序和二分查找使这一步的复杂度为 O(用例数 × log 常量数)。被测单元的结构置信度低、提取不到比较常量时，这一项为未知。

**断言。** 用例中没有任何学到的断言词时，提示它可能没有检查结果；断言的参数只涉及 mock 词时，提示核对行为结果。调用约束本身就是需求时（例如不能重复扣款），Agent 说明后保留。

## 3. 变异与保留集合

动态检查开启时，用变异判断每条候选用例是否守住了独有的行为。

### 变异算子

全部在词流上操作：关系运算互换、算术运算互换、`&&` 与 `||` 互换、整数加减一、布尔字面量互换、删除改动块中的一整行。这些替换不保证在每种语言里都合法，由项目自己的构建判断：无法构建的变异记为无效，并按扩展名记录各算子的无效比例，无效比例高的算子之后不再生成。

### 范围与抽样

只在需要保留的变更簇上生成变异：撤回试验确认需要的簇；没有撤回试验时，取可信度低的簇。变更簇和算子组成若干层，按各层的大小成比例随机抽样，逐个加入。

何时停止抽样用 Good–Turing 估计。把每个变异的**发现集合**（被哪些用例发现；没有用例发现时为空集）看作它的类别：已抽样 N 个有效变异，其中 N₁ 个发现集合在样本中只出现过一次，下一个变异带来新发现集合的概率约为 N₁/N。发现集合相同的变异对约简没有区别，只有新的发现集合可能改变保留哪些用例。这个估计低于精度参数，或预算用完时停止。

### 发现矩阵

每个变异单独作用到副本上，运行一次。能从输出中解析出单条用例的结果时（见 [输入与执行协议](languages.md#运行结果)），一次运行就得到所有用例对这个变异的结果，即发现矩阵的一行；解析不出时，整条命令作为一个结果。运行次数等于抽到的变异数，由上面的停止规则和预算控制。

变异不成组运行，因为两个变异的效果可能互相抵消：一个让结果加一、另一个让结果减一，同时启用时，检查两者之和的用例照样通过，会被误记为两个都没发现。这样记错的矩阵会把有用的用例列为删除候选，还会报出不存在的测试缺口。

### 约简

1. **去掉冗余变异**：凡是发现 m₁ 的用例都发现 m₂ 时，m₂ 冗余（Ammann、Delamaro、Offutt，2014）。用位集计算。
2. **选出保留的用例**：从保留集合出发，用贪心集合覆盖补入能发现剩余变异的候选用例：每次选新增发现最多的一条，同分按稳定顺序。近似比为 ln Δ + 1，Δ 是单条用例发现的最大变异数。
3. **确认**：未被选中的候选用例是删除或合并候选。把它们去掉后，在不含变异的副本中运行一次保留的用例，确认全部通过，排除用例之间的依赖；发现关系以逐个变异运行的结果为准。

不执行需求相关代码的用例、只测简单取值的用例、只断言 mock 调用的用例，都表现为没有发现任何有效变异，会在约简中成为候选。

发现集合相同，只说明对这批变异的检测能力相同。不同的输出约定、权限、幂等、副作用、时序和共享状态由各自的断言守护，合并前由 Agent 核对断言。

### 测试缺口

需要保留的变更簇上，有效变异没有被任何用例发现，这是有依据的测试缺口。只有这种情况才提示补测试，并写明未被发现的变异位置。没有变异结果时，不因“有逻辑却没有新用例”提示补测试。

## 4. 验证输入记录

### 验证输入

一次验证的结果由以下内容决定，它们的哈希称为**验证输入**：

- 仓库内容，但去掉同时满足两个条件的文件：按词法统计属于文档（自然语言比例高）；没有被任何代码或配置引用。引用核对用 Aho–Corasick 一次扫描代码和配置的全部文本，包括注释，因为 Go 的 `//go:embed` 就写在注释中。文件路径、所在目录的任一级（仓库根目录除外）、文件名，或能匹配它的通配符出现在其中，都算引用。测试用 `filepath.Join("testdata", name)` 拼出路径时，`testdata` 目录下的文件因此仍计入验证输入。
- 实际目录、参数、命令中的环境变量和工具身份。

### 重复验证

验证输入与上次通过时完全相同，并且这条命令从未在相同验证输入上得到不同的结果（否则记为不稳定），本次运行不会提供新信息：拦截一次，把上次的输出原样交给 Agent。拦截原因写明：环境变量或外部服务有变化时，用 `note_add` 写明理由后重跑。记录跨 session、跨 Agent 有效。

以下情况照常运行：用户要求重跑；Agent 用 `note_add` 记录了指向上一条验证的重跑理由（只用于下一次相同验证）；上次失败、中断或结果未知；命令会生成文件或自动修复等写入；混合命令中包含其他必要操作（这时不拦截整条命令）。两次运行之间，Agent 的命令中出现修改环境变量的写法（如 `export`、`source`、`unset`）时，只提示可能没有新信息，不拦截。

验证输入不包含 Agent 之外的变化：用户在其他终端修改了环境变量、数据库或服务时，TaskBelay 观察不到，Agent 按拦截原因写明理由后重跑。

只改注释或空白，验证输入照常改变，因为 doctest、构建标签、lint 和格式检查都可能读取注释或空白。按命令积累记录：某条命令在“只改注释”的前后多次结果一致、从无反例，且按 Beta 分布估计的不一致概率低于精度参数，才把它记为对注释不敏感。此后只改注释时，再次运行这条命令只提示可能没有新信息，并附上次输出，不拦截。

这个条件比“整个工作区相同”宽得多，有现成先例：`go help test` 说明，Go 的测试缓存只要求同一测试二进制和可缓存的参数，以及测试打开过的模块内文件和读过的环境变量不变，不核对数据库或网络等外部状态。

### 范围包含与通过规律

程序、子命令和其余参数都相同的命令，按路径参数的包含关系比较：`./...` 包含 `./internal/x/...`，不带路径包含所有路径。在相同验证输入上已经通过的较大范围，覆盖较小的范围：运行较小范围时提示可能没有新信息，并附较大范围的输出。

此外，从本仓库的运行记录中统计“A 通过时 B 也通过”的规律，例如“测试通过时构建也通过”：在相同验证输入上从无反例，且按 Beta 分布估计的反例概率低于精度参数时，规律成立。A 已在当前验证输入上通过时，运行 B 只提示可能没有新信息，并附 A 的输出。这些都不需要预先知道任何工具。范围包含和通过规律都是由运行记录推断的，不作为拦截依据。

## 5. 停止与报告

保留测试和本次是否运行它分别决定：本次没有运行某条用例，不表示它应该删除；历史测试不因当前任务没有涉及而成为候选。

报告分别列出：重复候选和测试预算、发现矩阵的规模和确认结果、保留集合、测试缺口、拦截的重复验证与复用的结果、可能没有新信息的提示，以及未运行或未完成的部分。实际运行次数、拦截次数和复用次数分别计数；TaskBelay 自己在副本中的运行计入总成本，不靠减少 Agent 的命令数掩盖新增的开销。

## 6. 反馈示例

```text
[建议] TestParseRange 的 1-3、2-4、5-5 三行
  被测单元 parseRange 的分段点是 0 和 10，三行输入都在 (0,10) 区间内，断言形状相同。
  变异：三行发现的变异集合相同；只保留 5-5 即可维持发现集合（已确认运行）。
  可删除 1-3、2-4；其他断言守护的输入约定请核对后保留。
[拦截] go test ./internal/export/...
  验证输入与 2 分钟前通过的那次相同（之间只修改了 README.md，它没有被代码引用）。
  上次输出如下……环境变量或外部服务有变化、需要重跑时，用 note_add 记录理由后再运行。
```
