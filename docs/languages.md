# 分析输入与验证执行

本文说明分析需要哪些信息、如何核对分析结果，以及验证操作怎样执行。不同开发语言使用同一套数据表示和判定方法，不再按文件级、代码级、测试级划分支持范围，也不要求逐种语言实现规则表或 Runner。

当前程序仍包含 `internal/lang`、`internal/codescan` 和 `internal/testrun` 的语言适配实现。本文规定的新接口尚未实现；已有 `test.<语言>.*` 配置仍按当前实现解释，不接受本文尚未定义为接口参数的数据。

## 内容与改动

所有文件先作为字节内容、路径和版本处理。规范化记录包括工作区身份、文件身份、内容摘要、范围、变更类型、来源与完整性。

- 新增和修改定位到当前内容；删除保留编辑前内容及来源。
- 移动和改名优先使用可核对编辑记录，唯一对应时迁移位置；不能唯一对应时保留待更新状态。
- 目录枚举、忽略边界、子模块与嵌套仓库也是输入范围的一部分，未观察内容不能假定不存在。
- 生成代码、外部依赖、测试及数据可以按项目说明和内容证据分类；文件后缀和名字只提供候选，不能独立决定生产责任、授权或是否可删除。
- 格式、注释与机械性改动可通过差异核对判断影响，但不能仅凭摘要不同或相同就推断业务变化。

文本范围可使用字节区间并附行列显示；二进制或不可拆分内容按整体记录。不要求输入必须存在函数、类、方法或 AST。位置只负责定位，语义角色另有证据。

## 分析结果与复核依据

分析需求、差异、项目材料和实际观察后，可以提出实现机制、行为关系、替代方案与待验证问题。这些结果在核对前均为候选，至少包含：

| 字段 | 用途 |
| --- | --- |
| 内容与关系类型 | 明确表达“使用”“共同满足”“可能影响”或“检查某行为”，不混用 |
| 来源及具体位置 | 指向消息、文件内容版本、范围、命令观察或已有证据 |
| 成立条件与适用范围 | 说明依赖哪些配置、环境、调用或用户要求 |
| 可信状态 | 已核对、候选或未知；失效后保留原记录 |
| 提取与复核版本 | 防止不同模型、规则或协议版本的结果被无条件混用 |

Agent 的解释可以作为检查线索，不能自行批准新需求。复核与原分析使用相同来源时，只算一份证据。超图推导和成本优化均依赖输入正确，不能消除语义分析中的错误。

这些分析结果可以来自语义提取器、项目已有工具或人工说明。本设计不指定模型厂商，不默认上传源码；引入外部服务需要相应授权。传输接口、复核方式和数据字段须在实施时确定。

## 验证操作

验证操作使用统一结构描述，算法不限定 `go test`、`pytest` 等具体命令：

```text
Action = {
  identity, program, argv, cwd, environment,
  input_manifest, prerequisites, obligations,
  output_contract, cost, effects, execution_conditions
}
```

上述结构说明验证操作需要包含哪些信息，尚未作为 MCP 或配置文件的公开 schema 提供。候选操作可以来自项目已有入口、脚本、说明和已观察的命令。无法识别的命令仍保留调用记录，无法确定的部分注明未知。

`program` 与参数尽量分开，保留原 shell 执行语义；复杂命令仍由原 shell 执行，TaskBelay 不通过不完整解析重写它。实际目录、环境前缀、重定向、后台任务及混合写操作分别核对。比较摘要不保存凭据原文。

### 输入清单的完整性

输入包括已使用内容，也包括可能改变选择结果的范围：

| 输入 | 需要记录的条件 |
| --- | --- |
| 文件 | 内容、路径身份及必要元数据，不能只比较修改时间 |
| 目录发现 | 枚举范围与版本，新文件出现会使相关结论失效 |
| 缺失对象 | “该路径不存在”等否定依赖，后续出现必须触发失效 |
| 配置与工具 | 影响行为的配置、可执行程序及版本 |
| 环境与外部状态 | 与本次输出有关的变量、服务或数据版本，无法核对时注明 |
| 输出 | 要求验证的结果，以及复用时必须仍存在的产物或效果 |

执行跟踪只提供它实际观察到的部分，不能证明未跟踪分支没有依赖。未核对的输入标记未知范围；核对整个工作区也不能替代外部状态核对。

## 结果与证据

操作结果记录是否实际启动、运行中或已结束、退出状态、输出来源、时间和适用输入版本。宿主字段不足、输出无法绑定调用或结果仅有 stdout 时，保留未知，不从“success”等普通文本猜退出码。

输出约定说明怎样把结果映射为证据。例如构建成功只回答构建问题；测试通过还需确定实际执行对象、断言与环境，才可能回答对应行为问题。工具报告覆盖行、变异或发现集合时，按其原始含义保存，不扩大解释。

实际调用、报告复用和相同来源的重复展示分开计数。未启动、被拦截和未完成动作不能计作已通过验证。

## 执行条件与限制

TaskBelay 的动态检查默认关闭，开启或明确请求后，才按固定快照在临时副本中执行相关操作。先确认实际入口使用副本内容，再采用其结果；动态阶段达到时间限制时终止本次启动的进程并清理临时资源，保留已完成的独立观察。

项目提供已有命令、准备方式及可独立运行条件。依赖复用和输出路径必须具体核对，不能因为某语言通常采用某目录就认为安全。涉及数据库、服务、端口或共享状态时沿用已授权的项目约定，不自动创建基础设施演练或补偿流程。

Agent 自己执行的日常命令照常使用实际工作目录，TaskBelay 记录能够取得的信息。缺少沙箱、文件访问跟踪或跨进程观察能力时注明边界，不把不存在的宿主能力写成已支持。参数、路径和结果的可观察程度随 Agent、平台和 shell 而异，判定标准保持一致。

## 不同语言与工具下的一致性

用相同的事实、约束和操作结构改变语言名称、文件后缀或工具名称，判定结果应保持一致。再分别检验采集是否如实表达实际输入和未知范围。前者检验算法没有语言分支，后者检验真实接入质量；两者都不意味着任意源码的语义都能自动准确理解。

添加新的项目工具时，只需要提供符合协议的事实或操作，不新增一套过度设计或过度测试规则。旧语言适配器如继续使用，只能作为可选的事实来源；新算法不以这些适配器为必要条件。
