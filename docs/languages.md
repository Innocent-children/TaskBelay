# 语言无关的输入与执行协议

本文件定义统一输入：文件怎样变成词、单元和统计，命令和结果怎样记录，TaskBelay 怎样在副本里运行项目已有的命令。算法不按语言分级，不为语言设置规则表或 Runner；所需约定从仓库内容中学习。

纯计算分别由 `units`、`repostats`、`changes`、`signals`、`validation` 完成，副本运行由 `dynamic` 完成；`check` 负责与账本和接入连接。

## 内容与改动

所有文件先作为字节内容、路径和版本处理。记录包括工作区身份、文件身份、blob 标识、范围、变更类型和来源。

- 新增和修改定位到当前内容；删除保留编辑前内容和来源。
- 移动和改名优先使用可核对的编辑记录；没有编辑记录时，用 [变更簇](algorithm.md) 的移动检测，能唯一对应才迁移位置。
- 子模块与嵌套仓库记录边界和引用的版本，不展开为普通目录；未观察到的内容不假定不存在。
- 二进制内容不分词，按整体记录变化。

## 统一词法

一个确定有限自动机单遍扫描文件，复杂度 O(字节数)，把文本切成标识符、数字、字符串、符号和空白。字符串再分为两种：

- **短键**：形如标识符、不含空格的字符串，例如 `"delimiter"`。
- **自然语言句子**：含空格、常用词比例高的字符串，例如 `"field delimiter"`。

哪些引号是字符串定界符、哪些记号开启注释，不预先规定，按下文从仓库统计。

## 版面树与单元

用栈做括号配对得到一棵树，按缩进层级得到另一棵树，取与这个文件更一致的那棵：括号配对失败少、缩进与括号层级吻合时用括号树，否则用缩进树。树的节点叫**单元**；在大多数语言里，顶层单元就是函数、类型或配置段。单元的第一行叫**首行**，首行中低频的词是单元的名字。

配置文件同样建立版面树，每一层键是一个单元。

单元标识使用内容、父级首行和同层重复首行的出现次序，不使用行号。空白或兄弟单元的内容变化不重置标识；不同文件中的同内容单元分别记录。移动只有在内容能唯一对应时才沿用问题身份。

## 从起点学习的约定

以下约定按文件扩展名分组，从起点快照统计。词法计数与词流按 blob 缓存，起点 tree 变化时复用未变化的内容，再合并仓库计数和约定；约定变化时重新确定单元名字和置信度：

| 约定 | 统计方法 |
| --- | --- |
| 字符串定界符 | 在同一行内大多成对出现的引号字符 |
| 注释记号 | 常出现在行首、其后自然语言词比例高的符号序列 |
| 关键字与名字 | 在单元首行中文档频率很高的词是关键字（如 `func`、`def`、`pub`），低频词是名字 |
| 调用写法 | 标识符后紧跟左括号（含方括号、尖括号）的比例；比例低的文件不做实参分析 |
| 返回与抛出写法 | 单元最后一行最常见的开头词 |
| 测试内容 | 测试词汇、路径模式和运行输出中出现的用例名，见下文 |
| 约定入口 | 起点中定义后再没出现过的名字的模式，见下文 |
| 生成内容、锁文件和清单 | 文件开头说明生成来源的文字；几乎每个单元都含名字、版本号和哈希的文件是锁文件；很多单元含名字和版本号、不含哈希的文件是清单 |
| 依赖目录 | 自带清单和许可证文件的子目录 |

**测试内容。** 运行输出中出现的用例名所在的单元作为初始样本；还没有运行记录时，用路径中含 test、spec 一类词的文件作为初始样本。固定词表和初始样本，交替最大化同一个带先验的分类似然：按当前划分，用 Dirichlet(`Prior+1`) 的最大后验估计两类词分布和类别比例，即按 `Prior` 平滑；再把非初始样本分到对数后验更大的类，相等时保持原分类，初始样本始终属于测试。划分改变时目标严格增加，迭代到划分不再变化；用尽计算预算或取消时记为未知，不用未完成的划分产生相关建议。当前内容使用起点学到的同一模型，不用新增内容重新训练；未见过的词不改变起点词表。按最终划分计算带 Dirichlet 先验的对数几率比及其标准化值（Monroe 等，2008），供断言、mock 和夹具相关词识别使用；词表只有一个词时不计算对数几率比。

**约定入口。** 起点中定义后再没出现过的名字，要么是死代码，要么由框架按约定调用。对这些名字的前缀、后缀、首行关键字和所在路径计数；某个模式中“只出现一次”的比例经二项检验显著高于全仓库的平均比例，这个模式就是约定入口，例如 `Test*`、`main`。

## 结构置信度

每个文件有一个结构置信度，由版面树的一致性、该扩展名的统计样本量和调用写法比例组成。置信度作为一项信号参与 [合并信号](algorithm.md)：初始权重使结构信息少的文件上的建议可信度较低，之后按反馈拟合，不会因为信息少而得出强结论。

## 命令与运行记录

每次命令记录：

| 字段 | 内容 |
| --- | --- |
| 身份 | 程序、参数、实际目录、命令中的环境变量和 shell 写法 |
| 工具身份 | 程序的实际路径，以及它的内容哈希或版本输出 |
| 结果 | 是否启动、退出状态、输出、开始和结束时间 |
| 工作区 | 运行前后的工作区状态 |

复杂命令仍由原 shell 执行，TaskBelay 只记录解析结果，不改写命令。环境摘要只保存比较用的哈希，不保存凭据原文。

命令是不是验证，由行为判断，不用命令名白名单：运行前后工作区不变，且输出出现已识别的用例名，或在不同代码快照上反复运行的命令归为验证。记录不足以判断时按普通命令记录，不作重复判断。

## 运行结果

退出状态取自 Agent 提供的结构化结果；拿不到时为未知，不从输出文字猜测。

后续已结束的运行可更新起点的测试识别，内容缓存保持不变。单条用例的结果从输出解析：用例名来自测试单元；“通过”和“失败”的标记词通过比较退出状态为零和非零的输出学习得到，只在失败输出中出现在用例名附近的词是失败标记。解析不出单条用例时，整条命令作为一个结果；输出没有正常结束时，文字中的成功标记也不能当作通过。

## 副本中的运行

动态检查由项目设置开启，或通过 `check_run(depth="tests")` 请求。开启后，撤回试验、变异和探针按以下方式运行：

1. **只运行可信命令**：只使用 Agent 在本任务中已经在真实工作区运行成功的验证命令。
2. **写时复制的副本**：从固定快照导出副本，文件系统支持时用写时复制（APFS 的 clonefile、Linux 的 reflink），否则普通复制。
3. **确认命令读的是副本**：先在副本上运行一次，作为当前快照的结果；再用破坏文件字节内容的哨兵改动核对命令是否读取该文件。命令仍然通过时，说明它不读这些文件或不在副本中运行，不能作为这些文件的验收依据。结果按命令和文件缓存。
4. **不影响真实工作区**：运行前后核对真实工作区状态；发生变化时停止动态部分并报告。
5. **资源**：默认串行，项目设置声明命令可以独立运行时并行。以较低优先级运行，Agent 开始自己的验证时暂停。
6. **预算**：每次副本运行使用动态检查的剩余预算，搜索阶段先扣除为确认运行保留的部分。启动前，将该可信命令在真实工作区最近一次成功运行的实测耗时与当前阶段剩余预算比较；不足以运行一次，或实测耗时未知时不启动，记为未知并说明剩余预算和实测耗时。等待、准备副本之后再次核对；历史耗时只用于判断是否启动，实际运行仍受当前阶段截止时间控制。到期或取消时终止本次启动的进程组，清理副本，保存已完成的确认结果。

涉及数据库、服务、端口等外部状态时沿用项目已有的约定。Agent 自己的日常命令照常在真实工作区运行，TaskBelay 只记录。

## 普适性的验收

把整个仓库中的某个扩展名一致地换成另一个，或把工具名一致地改名，统计按新的扩展名重新分组，命令仍按行为归类，结果应与原来相同（同分时按稳定规则排序）。这检验算法没有语言分支。

不同语言的差异只体现在统计结果和结构置信度上：版面规整、样本多的文件得到更强的结论，结构信息少的文件结论更少。添加新的项目或工具，不需要新增规则。

## 输入不足时的处理

自然语言文件只有在存在完整句子、没有执行结构且不属于清单或配置时，才作为文档候选；无法确定的文件仍计入验证输入。注释、目录和 glob 中引用的文档也计入。

无法区分构建失败与行为失败时，发现矩阵按 [过度测试判定](over-testing.md#发现矩阵) 保留未知。

副本运行核对工具文件的内容摘要、环境摘要和目录，拒绝重放混合、写入或无法完整解析的命令。macOS 使用文件 clone，Linux 使用文件系统 reflink；不支持时逐字节复制，Windows 使用逐字节复制。每次运行有独立目录；POSIX 进程组与 Windows Job 负责暂停、恢复和清理后代进程。
