## 从命令到判断

`internal/hook/verifications.go` 的 `Tasks.BeforeCommand` 解析整条命令。只读分类决定是否采集运行前观察、调用 `check.Verification`；两条路径随后都调用 `Store.BeginVerification`。执行结束后，`Tasks.AfterCommand` 调用 `Store.EndVerification`，按宿主的完成状态和退出码保存结果。因此账本同时保留普通查看、可能影响外部状态的操作以及验证命令。两个样本的 `passed` 都有执行依据；是否认作验证另由 `scope.Validation` 表示。

**t4 的读取。** 两段均为 `read_only`，整条命令满足 `shell.Script.ReadOnly()`。前置没有采集观察，也没有进入重复判断；后置的 `check.CompleteVerification` 保存输出和原 tree 后，在只读分支返回。因此 `scope.Hash` 为空、`Cases=null`、`Validation=false`。建立测试索引时，即使 `Store.IndexVerifications` 查到这一行，`internal/check/snapshot.go` 的 `runSamples` 也会排除它。作为两次其他验证之间的操作，这条读取没有环境变更标记，`validation.Evaluate` 不会据此降低复用置信度。读取输出里的源码或用例名没有成为学习样本，也没有触发重复提示或拦截。

**t6 的测试识别。** 解析器把中间的 `go test` 段标为 `verification`、语言为 `go`，另两段为 `other`。前置已有观察 335，`check.Verification` 计算了整条命令的输入摘要（纳入 285 个文件），并调用 `validation.Evaluate`。当时没有同键运行，`validation.IsValidation` 返回 false，尚未比较重复输入。后置观察的 tree 与前置相同。此时 `check.CompleteVerification` 从任务起点已发布索引的 `case_name` 查找输出中的用例，再由 `executed` 核对报告格式、排除照抄源码的名字。

首个能定位的用例识别断点在**起点索引的候选名**。005 会话第 91–92 行新增 `internal/signals/cases_test.go`，第 101 行生成带另一用例名的 overlay 探针。按 t6 起点 `3dfcb24e08638e1506d739dc20e018f0eaab6741` 检查快照中的基础索引、两个已保存派生索引及各自父层，两个实际运行名在 `case_name` 和 `fold_name` 中的有效条目均为 0。输出的诊断文字还提到已有的 `TestDeliveryFeedbackRecords`，它在索引中，但本次没有该用例的 RUN、PASS 行。最终 `scope.Cases=[]`。后备判断要求同键有已识别用例，或至少在两个不同 tree 上各执行一次且每次前后 tree 不变；本例只有一个 tree、一次执行，故 `Validation=false`。

**t6 的输出实际进入了学习。** `taskIndex → runSamples → observedNames` 接受同算法、已执行、有退出码和结束时间的非只读命令，不要求 `scope.Validation=true`。`observedNames` 从起点的单元名中筛选运行证据。按 `internal/check/index_update.go` 的取键方式，用算法、基础索引 ID 和原样输出摘要查 `analysis_cache_v12`，`run-names` 键 `096b18289f523fc0a025e7a0462ca56847c02aec34686b42cf2f69a0dd4f2cf5` 实存 `[]`，同工作区没有另一条相同输出。该输出已经被处理，贡献的用例名为零。

**相同输入下能否复用。** t6 的整条脚本为 `complex=true`、`sequential=true`，含三个命令段。按 `internal/check/verification.go` 的 `command` 得到 `Unknown=true`、`Mixed=true`。实际 `scope.Tool` 为空，顶层 `environment_id` 有值，`EnvironmentChanged=true`。`validation.Input` 即使生成哈希，也只在工具和环境标识齐全且命令已知时标为完整，本例 `Complete=false`。即使日后取得验证身份并请求相同哈希，`internal/validation/history.go` 的 `Evaluate` 也会先因命令未知或输入不全放行，走不到相同哈希的提示或拦截；可完整比较的混合命令才可能只提示。这是对规则的条件判断。快照中没有第二次同键请求，也没有漏拦的实际事件。`analysis.tests=off` 控制动态检查，前述命令前后 hook 和按运行输出学习均没有这个开关条件。

如果 t6 出现在另一条验证的两次运行之间，它还有一项用途：`Evaluate` 会把它视为可能改变外部状态的中间操作，在其他条件原可拦截时降为提示。这里依据的是本行的环境变更标记和非只读组合操作；本轮没有观察到因此降级的后续决定。
