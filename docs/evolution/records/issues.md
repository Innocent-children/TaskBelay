# 未启动候选的原始观察

## 最终结果摘要

TB-003、TB-004、TB-006 保留候选状态，尚未形成已验收的产品修复。这里只保存原问题池的详细观察与调查入口；状态和下一步统一在 [产品问题池](../backlog.md) 维护。

以下观察来自原问题池记录的 2026-11-12 本机核查及用户转述的另一模型报告。转述须结合原始事件确认，不作为原因已查明或应立即修复的证据。

## TB-003

`expect`、`workspace`、`login` 的近似重复提示出现多次；Agent 用笔记解释后保留。

原定调查入口：选一处核对具体代码、用途和输入变化。建议不成立则形成误报样本；理由仍成立却重复提示则形成重复负担样本；建议正确但未行动则核对提示是否可执行。[009](009.md) 收尾另记旧样本在当时数据中不可复核，不据转述改算法。

## TB-004

用户转述的报告称实验副本任务有 13 次 hook、2 次 MCP 超时。

原定调查入口：从原始错误定位耗时环节、版本和并发条件，确认是否阻断核心检查，再决定是否修复。

## TB-006

一个会话在创建任务前已有约一小时活动，早期关联为空。

原定调查入口：核对其间应关联的开发行为、触发条件和原始事件，结合会话记录判断接入完整性。
