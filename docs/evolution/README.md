# TaskBelay 迭代流程

TaskBelay 通过真实业务需求重演，观察工具是否减少了多余的设计、测试和验证，再依据具体问题改进产品。本文件是唯一的迭代流程定义；评估口径见 [评估与验证方法](evaluation.md)，长期目标见 [产品需求](../product.md)。

## 资料分工

| 资料 | 维护内容 |
| --- | --- |
| [业务样本池](samples.md) | 脱敏业务需求的编号、摘要、阶段、关联记录与下一步 |
| [产品问题池](backlog.md) | TaskBelay 问题的编号、摘要、状态、关联记录与下一步 |
| `records/` | 每轮冻结的任务约定、阶段事实、证据、复盘和最终决定；沿用原编号 |
| 本机受保护资料 | 完整需求、来源映射、历史参考和原始会话；批次运行现场由本地 `batch-state.json` 保存 |

两类池只维护索引，详细契约和结果写入关联记录。产品设计文档描述已采用行为，候选文档随候选一起评估。公开记录不复制实时运行配置；模型、任务数量、具体预算、安装版本与分支按每次授权记录在本机批次资料中，不作为永久流程。

## 迭代步骤

```text
准备真实业务需求 → 独立副本重做 → 独立复盘 → 形成产品问题
                                              ↓
继续真实任务 ← 采用决定与安全切换 ← 有限修复验证
```

主持 Agent 负责准备任务、隔离参考资料、收集证据、安排复盘和作出采用决定；开发 Agent 根据任务说明自主实现。每个任务和每次独立复盘使用新会话。

### 1. 准备真实业务需求

在授权范围内，由主持者在独立历史参考副本中只读还原业务目标、实现前基线、逐项验收及必要依赖。历史实现用于核实需求和取舍，不是唯一正确答案；顺手修改和旧缺陷不自动成为验收。信息不足、依赖不可安全替代或预算内无法完成的任务先暂缓。

分开保存来源映射与开发任务说明。开发会话只取得目标、可观察验收、基线约定、必要依赖和安全执行方式，看不到参考提交、参考 diff、后续代码或实现答案，也不能通过 Git 对象、共享目录或其他会话获取这些资料。

开工前冻结本轮需求、范围、必要行为、验收、基线、比较方式与依赖；按本次授权填写开发、验证、复盘、返工的数值上限和停止条件，预留复盘与收尾投入。批次授权另写清允许读取和操作的范围、模型与审核设置，以及安装、提交、评审、推送、合并权限。

### 2. 在独立副本中重做

原业务仓库只读，历史参考与开发副本隔离访问，不共用可暴露后续提交的 Git 对象或 worktree。开发副本只保留实现前基线及必要内容，另建本地历史，不关联业务远端，不回写原仓库或触达真实业务系统。启动前核对远端、子模块、依赖地址、脚本与配置；数据使用脱敏或合成的最小样本，不复制凭据或真实敏感数据。

固定运行版通过实际 hook + MCP 约束业务重演和候选开发。按实际事件及调用核验每个会话接入，首尾校验所用程序版本；源码候选与运行版分开保存。各任务和对照组使用独立数据，需要旧状态时从同一份脱敏一致快照开始，不借用用户活动账本。

开发会话自主处理任务和反馈，主持者保存原始需求、起点与最终 diff、执行记录及工具输入输出。人工干预另记原因和影响。达到开发上限即停止开发，将已有产物交付复盘，不为赶时间删掉必要行为。

### 3. 独立复盘

另开会话，先提供需求、产物与执行事实，遮蔽工具判定和处置理由；保存独立判断后，再开放工具反馈。分别记录业务验收、环境阻塞和检测有效性，按 [评估方法](evaluation.md) 核对多余工作、必要行为、误报、漏报与成本。

明确实现缺陷可在冻结范围和剩余预算内定向返工，保留各次结果，返工后再以新会话独立复盘。没有可改变判断的新问题时，不追加验证。业务任务期间不切换运行版修复 TaskBelay。

### 4. 形成产品问题

把复盘或日常使用中可核对的过度设计、过度测试、误报、漏报和额外负担记入产品问题池，关联样本、具体输入链、必要行为与证据缺口。没有发现产品问题的业务重演也是有效观察，不必生成修复项。

优先处理已定界且影响核心判断的问题。现有条目尚未定界时，只在本次预算内有限调查；无关新问题留作候选，不扩入当前实现。没有可执行产品问题时，转向已授权的真实需求获取证据。

### 5. 有限修复与验证

从具体输入链复现问题，固定期望行为、最小反例和最近的必要行为对照，再确定最小修改及维护成本。候选在独立分支或副本开发，由固定运行版约束；不让未采用实现混入后续基线。

验证只回答当前缺口，按 [评估方法](evaluation.md) 选择范围，核对受影响旧缓存、检查记录及规则版本。保留每次失败、返工与未知；达到预算即保存状态，不反复追加规则。候选仍须独立复盘，只有会改变决定的缺口才补充验证。

### 6. 决定采用并安全切换

| 决定 | 条件与处理 |
| --- | --- |
| 采用 | 验收满足、必要行为和用户修改保留、目标问题明确改善，新增负担可接受；注明适用条件 |
| 保留旧版 | 未改善、误伤必要行为或成本不合算；保留失败候选及拒绝依据 |
| 无法判定 | 接入、原始证据或比较条件不足；保留旧版并写明缺口与恢复条件 |

调查和业务重演以证据及结论交付，不要求产生候选版。接入或记录修复按自身验收判断，核心省工效果单独记录；消除一个误报不能证明整体有效。

源码采用与运行版安装分别记录。先保存被接受源码与可复现构建标识，按本次授权完成提交、评审或合并；共享安装等安全时点再切换，切换前保留可恢复程序与一致数据备份，涉及格式变化时说明程序和数据的配套恢复方式。仍有用户任务使用共享安装时，停在“运行版待切换”。安装后用新会话核验实际 hook/MCP 接入。继续迭代不代替安装、推送或合并授权。

### 7. 收尾后继续

更新本轮最终摘要、阶段记录及两类池的状态和下一步。只在授权有效、预算有余、运行基线与接入明确且存在可执行任务时继续；采用版在完成安全切换后进入后续真实任务，未采用则保留旧版。

没有合适产品问题就选择已授权业务样本；没有信息充分且可安全执行的真实需求时，写明样本缺口。隔离、接入或固定版本无法保证时暂停受影响任务；连续尝试不能增加可靠证据或明确改善时，停止重复候选实现，复查假设和观察方式。用户要求停止或总预算用尽时立即保存状态，等待重新授权。

## 状态与恢复

样本阶段使用“候选 → 可重演 → 进行中 → 已复盘”；信息不足记“暂缓”，不再适用记“关闭”。“已复盘”只表示评价已保存，业务验收仍分别记录完成、部分完成或未完成。用户中止且未复盘的任务明确记为“已停止、未复盘”，不能列为已验收。

产品问题使用“候选 → 待办 → 进行中 → 完成”，也可暂缓或关闭。待办须有范围、验收与预算；完成以该问题验收为准。证据不足或失败后暂缓，恢复条件满足才重新定界；已证伪、重复或不值得继续则关闭。沿用原编号并关联失败记录。

中断前保存当前步骤、最后有效输出、已用预算、返工次数、阻塞与恢复条件。恢复须先确认授权，再核对当前工作区、历史隔离、运行程序、数据与已保存结果，计入剩余预算。用户修改以当前内容为准；可核对的结果复用，比较条件失效则明确无法判定。

## 记录与保留

原始资料保存在受保护且不进入 Git 的本机目录，保存来源映射、关键事件和校验值。公开仓库只保留脱敏结论、证据编号及最小可公开复现，不包含公司私有代码、路径、提交、凭据或原始会话。活动记录及仍被结论引用的证据保留；清理失效资料前注明哪些结论将不能重放。测试与临时样本的取舍见 [评估方法](evaluation.md#验证选择与样本价值)。

每轮记录使用以下内容，原编号不变。顶部写最终结果，后续按阶段保存事实；阶段中的“待复盘”“未安装”只说明当时状态，不覆盖后续决定。历史路径与时间保持原貌，仅作为历史定位依据。

```markdown
# NNN：任务标题

## 最终结果摘要
任务或问题编号；业务验收、环境阻塞和检测有效性；采用决定；源码与安装的各阶段结果；未知及下一步。

## 冻结的任务约定
需求与来源；范围及必要行为；逐项验收；依赖与安全边界；本次预算、返工上限和停止条件。

## 基线与执行
起点及隔离方式；实际接入与版本校验；执行事实与干预情况。完整配置和私有来源留在本机资料。

## 证据与独立复盘
证据编号；最小反例与必要行为对照；各次独立判断、验证及失败结果。

## 决定与收尾
改善与成本；采用、拒绝或无法判定的理由；剩余授权事项；关联样本和产品问题。
```

启动、关键证据或阻塞、采用决定、切换等待和收尾时主动汇报实际结果与未知。
