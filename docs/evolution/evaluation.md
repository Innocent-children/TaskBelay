# 评估与验证方法

本文定义怎样依据证据判断正确性、误报漏报、实际收益与成本。任务准备、独立复盘、修复、采用和继续的执行规则统一见 [迭代流程](README.md)；样本见 [业务样本池](samples.md)，具体结论保存在关联记录中。

## 验证选择与样本价值

验证服务于当前问题，选择能提供新信息的方法。文档变更做必要的阅读、引用与一致性核对；行为改动先用最小复现和直接相关的正常对照。命令重复时核对前后代码、命令和环境输入；代码修改后的相关复测可以提供新信息，不能仅凭次数认定过测。

安装与交付基础测试继续维护。算法和业务模块可保留对应已确认失败模式或产品约定的回归测试、最小问题样本与必要重放工具，说明它们保留了什么必要行为。同一失败模式复用最小用例；探索脚本、重复产物及失效断言及时清理。用于调整算法的样本只支持回归结果，其他真实需求才提供新的适用性证据。

## 证据与结论

验收依据业务目标和可核对的必要行为，历史实现可辅助核实取舍，不是唯一答案。评估依据原始需求、基线与最终 diff、执行记录、实际 hook/MCP 输入输出、Agent 回应及最终产物相互印证，保留证据缺口和分歧。先有独立判断再核对工具反馈，避免按工具结论寻找理由；具体会话分工见迭代流程。

| 分开记录的结论 | 所需依据 |
| --- | --- |
| 业务验收 | 各项完成、部分完成或未完成，必要行为及相关既有行为是否保留 |
| 环境与执行范围 | 哪些依赖已安全隔离，哪些验收因环境阻塞未执行，哪些结果仍未知 |
| 检测有效性 | 实际输入与反馈、Agent 回应、最终产物和处理成本，哪些多余工作被减少或仍被放行 |

环境阻塞不直接算检测失败，部分交付也能提供可核对的误报或漏报证据；未执行、失败和未知不能记为通过。提示数、拦截数及建议采纳数只描述过程，不能证明省工。

## 要回答的问题

评估需要回答四个问题：是否准确识别了项目内容和仓库约定；算法是否满足文档规定的性质；TaskBelay 是否减少了实际多余的工作；节省的工作是否足以抵消工具运行和处理反馈带来的成本。理论复杂度、临时验证结果和真实 Agent 使用效果分别报告，不能相互替代。

| 层次 | 核对内容 | 不能据此推出 |
| --- | --- | --- |
| 输入与统计 | 词法、版面树、学到的约定、种子匹配和命令归类是否正确 | 统计结果合理不等于需求理解正确 |
| 算法 | 变更簇、需求相关区、分组检验、集合覆盖、验证输入等是否满足各自的性质 | 算法性质成立不等于实际效果好 |
| 接入与流程 | 是否正确处理实际事件、调用所属的会话和轮次、运行结果、授权及用户修改 | 构造事件通过不等于真实 Agent 已接入 |
| 端到端效果 | 交付行为、多余工作、误判和总成本的变化 | 减少代码或命令数量不等于效果更好 |

## 核心性质与边界

修改算法时，先沿真实需求、事件、文件内容与账本状态到反馈的输入链复现具体问题，再提取最小反例和必要行为对照，给出能独立核对的预期结果。合成输入可补充边界，不能独自证明真实问题已解决；无法取得真实链路时记录证据缺口。根据改动核对受影响旧缓存、旧检查记录与规则版本的失效及复用，避免候选继续消费过期结论。以下性质帮助选择必要范围，不要求每次全部核对，也不据此恢复整套固定语言规则。

| 对象 | 关键性质与反例 |
| --- | --- |
| 统一词法与版面 | 同一 blob 的分析结果不变；括号树与缩进树的选择稳定；二进制内容按整体记录 |
| 仓库统计 | 扩展名一致改名后统计结果对应不变；样本少时结构置信度降低 |
| 变更簇 | 撤回一个簇及依赖它的簇后，不留下悬空引用；构建失败时合并后重算；混有其他来源改动的簇不成为候选 |
| 需求相关区 | 常见词不传递关联；只经公共函数相连的顺手改动落在相关区外；没有种子时为未知 |
| 对外新增项 | 只比对名字和取值，说明文字不参与；登记为实现位置的项属于“Agent 说明”；只按形状识别、未经探针确认的项不拦截；“Agent 说明”及最终保留的“没有对应说明”项出现在交付报告中 |
| 间接层与近似重复 | 按成员名共现统计候选实现，不把候选数当作已确认的类型关系；实参文本相同、转发形状和旧名出现都只形成候选，反馈写明核对条件；调用写法比例低时参数分析为未知；相同变量名不当作恒定值；调用、返回和注释不当作声明；无主体或相似度为零不生成重复建议 |
| 用途核对 | 用成对案例核对重试、校验、隔离层和断言的实际效果。替换或撤销依据后，应能区分仍成立的建议与已无法确认的判断；只记录 Agent 接受了建议不能证明建议正确 |
| 撤回试验 | 只撤回 Agent 变更簇；相关区内的簇只在对应需求有自己的验收依据时作候选；受保护的防御性短分支和恢复分支不作候选；最终撤回集合经过确认运行 |
| 分组检验 | d 较小时，运行次数与 d·log₂(n/d) 同阶；d 接近 n 时，接近逐个运行；撤回补丁与确认运行采用的整组改动一致；确认失败后逐个加入候选，最终得到的集合能通过 |
| 变异与约简 | 每个变异单独运行；无效变异不计入发现结果；Good–Turing 按发现集合计数；冗余变异识别和贪心覆盖结果正确；保留集合中的用例不成为删除候选；删去候选后，保留的用例全部通过 |
| 验证输入 | 未被引用的文档变化不改变验证输入；通过注释、目录或通配符引用的文档变化会改变验证输入；注释敏感和不稳定的命令不复用；范围包含、通过规律和注释不敏感只提示；两次运行之间修改过环境变量、结果未知、会写入、用户要求重跑时放行 |
| 合并与校准 | 相关信号一起拟合，不重复计数；根据实际处理和恢复情况记录标签；某类建议被判定为不成立的次数增多时，该类建议排序下降；拦截只依据可核对的事实，与可信度无关 |
| 用户内容 | 混合片段不整段撤回；新快照发布后旧建议失效；工作区更新不新增授权 |
| 有限反馈 | 问题所在代码移动，或其他文件被修改时，不改变该问题的拦截标识；不能因为结果未知就拦截 |

核对算法复杂度时，应记录实际处理规模：变化的字节数、变更簇数、推送工作量与相关区大小、LSH 候选数、分组检验的候选数与实际运行次数、变异数与发现矩阵大小。小规模例子符合理论界，只能辅助检查实现是否正确；理论界仍依赖文档列出的前提，不能用样本结果代替证明。

## 普适性

检验内核是否依赖语言时，将整个仓库中的某个扩展名统一换成另一个，或统一更改某个工具名，然后重新分组统计。结果应与原来相同，同分时仍按稳定规则排序。这只能证明算法没有按语言区分处理。

真实项目按文本结构特点另行选择样本，包括括号结构、缩进结构、配置驱动、生成内容、脚本入口、多语言混合，以及不同的命令输出格式。分别核对学到的约定是否正确、结构置信度是否反映实际可靠程度，以及面对低置信度文件时，算法是否减少结论、而非给出更多错误结论。

## 正常开发与接续

选择与本次改动影响直接相关的流程，按事件发生顺序、实际文件内容和账本版本核对：

| 场景 | 验收 |
| --- | --- |
| 多次提交、部分暂存、amend | 起点不变，累计改动完整，实际索引不被改写 |
| 用户修改、删除、移动或改名后继续 | 基于当前文件继续工作，保留用户修改后的程序行为；无法确定旧位置现在对应到哪里时，记为未知 |
| 两个 session 并发编辑或更新需求 | 不覆盖较新记录，旧输入结果只保存为历史 |
| 切分支、stash、pull、rebase、暂停恢复 | 工作区更新与 Agent 编辑分开记录，任务记录不中断，有效决定继续生效 |
| 追加、撤销需求或用户决定保留内容 | 重新计算相关区与信号，不再依据已被撤回的授权执行后续操作 |
| 半自动范围内调整及待确认增补 | 范围内照常开发，仅新增未授权部分等待；精简建议不新增审批 |
| task_finish 后输入未变或已变化 | 分别处理原交付请求或过期请求，不循环强制验证 |
| 跨 Agent、压缩或隔天接续 | 仍有效的结果可以复用，尚不能确定的部分继续注明；不把旧的下一步计划当成必须重跑的指令 |
| 动态检查期间用户编辑 | 不锁工作区，旧结果不用于当前拦截，不自动反复重跑 |
| 结果字段缺失、超时或接入错误 | 记录真实完成程度，TaskBelay 自身故障不阻断正常工作 |

涉及平台、shell 和 Agent 时，注明实际环境、版本和观察到的结果。交叉编译、内部模型和构造事件的验证结果，只能说明各自验证范围内的情况。不能用一个平台或 Agent 的结果，推定其他平台或 Agent 也同样成立。

## 端到端对比

对照样本既要包含确有多余设计或重复验证的情况，也要包含应当保留抽象、执行大范围回归或进行随机采样的情况，不能只选容易精简的任务。

判断一次算法改动时，在相同需求、起点和运行环境下比较旧版与新版；判断工具整体净收益时，再比较关闭与开启 TaskBelay 的结果。固定并记录 Agent、模型、工具及设置，只改变要验证的因素，动态检查状态保持一致；确需比较它的开关时单独定界。用于验收行为的标准应由独立来源确定；核对是否出现新增失败、应保留的行为是否仍然成立，不用当前算法的分数充当唯一标准。

样本量与重复次数按要回答的问题、成本和统计不确定性确定。如果需要通过重复运行考察随机性，应预先说明假设、采样方式和次数上限；不能看到有利结果就停止，也不能为追求显著性无限追加。只有条件可比时，才能复用历史对照结果；否则应说明条件差异。

只有实际 hook/MCP 事件及首尾版本校验支持的样本，才能纳入固定版本比较。期间切换版本、接入缺失、超时或结果不完整的样本分别报告完成范围和失败率，不能从统计中删去。副本、数据隔离及执行安排统一见 [迭代流程](README.md)。

## 指标与解释

| 指标 | 解释 |
| --- | --- |
| 正确性 | 当前需求是否满足、直接相关的既有行为及用户修改是否保留；新增失败逐项报告 |
| 精简收益 | 减少了多少已经确认多余的改动，哪些维护成本降低或增加了 |
| 无效验证 | 不提供新信息的验证运行及其成本减少多少；必要验证是否被错误阻止 |
| 错误拦截 | 被拦截的改动和验证中实际必要的比例、数量与原因 |
| 建议质量 | 采纳建议后，是否保留应有行为并减少负担；采纳本身不等于建议正确 |
| 漏判 | 抽查放行和未提示的情况，核对仍存在的多余工作 |
| 依据质量 | 种子匹配、需求对应关系和仓库约定是否判断错误，是否误用了过期结果，以及哪些部分仍无法判断 |
| 使用连续性 | 用户修改是否保留、任务能否继续，以及重复提示与额外审批的次数 |
| 总成本 | Agent 与 TaskBelay 合计的实际耗时、模型 token、命令次数、资源用量，以及用户处理反馈的时间 |

代码行数、用例数、验证次数可作为辅助数据，不设必须下降的比例。不能通过删除必要测试、全部放行或让用户反复解释需求来改善表面指标。两个 Agent、动态检查开关和实际平台的结果分别报告；某一组的收益不能抵消另一组中应有行为被破坏的问题。

结果同时说明正确性、误判与漏判、目标问题改善和新增成本，报告样本数、分布及不确定性。具体修复成立而真实节省仍未知时，分别记录；消除一个误报不能证明整体有效。采用决定及切换条件见 [迭代流程](README.md#6-决定采用并安全切换)。除校准外，只有发现具体错误时才据此调整参数，不能为迎合历史断言更改需求。

## 性能与退化

分别记录词法分析与统计、变更簇计算、相关区推送、静态信号计算、信号合并与反馈选择、副本运行、序列化和提交结果的成本。总成本还应包含文件观察、Git 操作和环境核对；命中缓存时也有核对成本，不能只报告内核循环的耗时。

分别观察冷启动、内容未变时复用结果、局部内容变化、起点 tree 变化后更新统计，以及候选很多但静态信号不准（分组检验接近逐个运行）的场景。记录中位数、P95、峰值内存、完成比例和仍无法判断的范围，不能通过提前放弃分析来获得看似更快的结果。

核对时间预算用尽后，程序是否停止了相关工作、保存了已经取得的有效结果，并注明未完成的范围，用户是否仍能继续开发。预算是等待上限，不是实测耗时，也不是必须运行的时长；理论复杂度见 [算法核心](../algorithm.md)。

## 真实使用反馈

没有看到拦截或精简记录时，沿“可判断输入 → 检查执行 → 反馈送达并记录 → Agent 回应 → 最终产物变化”核对。分别判断检查没有运行、检查后没有发现问题、反馈未展示、反馈未处理和处理后没有收益；尚在进行的任务不能作为交付检查失败的证据。

`taskbelay hits --since 14d` 提供已记录的检查问题、拦截记录和后续处理情况。结果为空时，结合 debug、session-records 和触发条件核对覆盖范围。校准标签可用于复盘，但不能代替人工核对。样本同时覆盖被拦截的问题、仅建议的问题和已放行的操作，核对来源、判定条件与当前需求。

`written=true` 只能证明写出，不能单独证明宿主收到、模型看到、Agent 处理或最后减少了工作。按实际事件定位缺口，不把一段链路的证据当作端到端收益。
