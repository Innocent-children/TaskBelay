# 工程控制设计与验收

## 使用场景与当前做法

开发者授权一个真实开发结果及其限制，代理在实现与验证之间交替工作。旧 Core 用 11 个节点、文件清单、计划确认和宿主报告的检查推进任务。文件内越界不能由路径检查发现；检查声明不能证明执行；计划轮次重置用量；修改使整份下游记录失效；正常流程要求额外用户确认。

## 可用数据与责任

Core 保留可靠的只读 Git 观察器（工作区实例、固定基线、index/worktree 分层、内容摘要、历史关系），替换阶段流程及其数据模型。Core 负责授权契约、控制结论、验收关系及累计用量；repository 负责事实观察；execution 负责实际子进程、输入与环境指纹、结果与恢复收据；store 负责当前 Schema、原子 CAS、请求去重和有界记录；Host 负责从真实用户指令提取授权、语义审查和原有权限。CLI、MCP、WebUI 使用同一应用服务。Core 不修改 Git，也不替用户授予权限。

## 处理规则

- 一个当前授权契约保存目标、非目标、接口/数据/依赖/设计约束、禁止改动路径与检查要求，以及真实用户消息引用。授权已有时直接工作；新授权或改变重要取舍才询问用户。消息引用是可审计宿主声明，不是对话认证。
- 程序核对实际 Task diff、路径、冻结内容、依赖清单变化、变动量及工作区身份。路径候选与变动量是复核提示；禁止路径、冻结内容与未授权依赖变化是确定性阻碍。语义审查必须绑定当前内容与契约，逐路径关联目标，逐约束给出依据、结论和不确定性。语义依据仍是代理判断，程序不评分，不声称证明功能正确。
- 生命周期只有 active、done、cancelled；控制建议由当前事实推导为 continue、self_correct、verify、stop、ask_user。实现、局部检查、复核可以任意交替。finish 只在无确定性违规、语义结论完整且无未解决不确定性、全部目标有适用证据且无未确定运行时成功。cancel 不删除工作成果。done/cancelled 不能恢复成 active。
- 每个检查保存精确 argv、相对 cwd、理由、所覆盖目标、输入范围、环境条件、超时及失败策略。缺省输入为整个仓库；缩小范围须说明依赖依据，未声明的外部环境不视为已掌握。实际执行由 Core 的执行边界启动，不解释任意 shell 字符串。用户批准的检查命令可能有副作用，仍须遵守 Host 原生权限；系统不是沙箱。
- 检查开始前持久保存运行身份和消耗，实际返回后保存退出码、耗时、输出摘要及受限日志。检查通过与验收结论分离。宿主自述只能记录为 claim；明确用户检查单独记录为 human。两者不冒充 Core 执行。
- 证据绑定检查定义、涉及目标/约束、输入内容、所选环境和执行文件；修改后只使相应指纹变化的证据过期。不相关文档修改可保留范围明确的检查。没有依赖依据时使用全仓输入。相同内容线性提交不应失效。
- 预算是 Task 生命周期累计值：运行次数、执行时间、Core 调用/观察/分析时间，以及单独标明的宿主报告时间、等待和 token。修订不重置；额度不足不能免除验收。预算变化须有真实用户授权。精确失败重复需新假设或真实输入变化，不能无限重试。
- 持久保存最新契约、进展、失败尝试、有效/过期证据及未确定运行。响应丢失先读取相同 operation_id；保存结果不重放进程。崩溃遗留运行不自动重试，不以“进程结束”推断检查通过。收据能恢复真实结果；没有收据则明确不确定，核对操作后仅解除该不确定性，仍须取得新的真实证据。
- 热快照保留当前记录与有界近期历史，旧运行/事件按策略压缩，累计成本不丢失、有效证据与未确定操作不删除。终态任务的清除必须显式授权；旧 Schema 拒绝打开，不迁移或自动删除用户数据。

## 风险与非目标

不能验证代理语义判断真实，也不能保证代理遵守可绕过的调用边界。未通过 Core 执行的 shell、远端检查、数据库及其他服务不自动受控。执行结果证明特定条件下的命令结果，不证明测试本身足够。保留本地优先、原有安装/工作位置能力；不增加编码模型、任意工作流、云平台、Git 发布或安全沙箱。旧内部协议与旧 Task 数据无兼容层。

## 预期效果与验收方式

在 Windows 本机临时 Git 仓库中实际执行代表性开发：修复一项函数行为并运行其测试；在同一路径加入非目标变化；更改依赖；增加独立目标；修改代码使相关证据过期而保留独立证据；失败后修复；丢失响应后读取；中断执行后恢复；跨多次修订与历史压缩检查累计消耗不变。CLI/MCP/HTTP 和四个 Host 安装产物使用同一契约。

对照基于同一场景与同等验收条件的旧 main Core：实际触发旧节点提交、宿主自述的自动检查、全局失效和计划轮次用量；不把静态推断、脚本场景或适配器测试写成真人 Host 效率实验。记录能证明的能力差异与不能证明的净收益。实机 Host、其他操作系统与长期用户收益没有执行时明确列为未验证。

## 实现前评估

1. 恢复读最新契约、事实与不确定操作，不重建阶段；2. 控制依据含真实 Git 与执行收据；3. 用户仅看结果、缺口和必要决定；4. 可用本地 Core、安装适配器及真实 Host 验证，Host 未执行须明示；5. 只有 Core Task 状态；6. 删除阶段审批与工作流表单；7. 以开发结果、有效证据、越界处理及累计成本验收，不按界面或新增组件计数。

全部本地调用（包括未关联 Task 的查询）记录在 control_cost；wall_ms 是实测或当前进行中的墙钟，unknown_ms 是崩溃遗留调用的保守额度，pending 是尚未结算项。Core 墙钟与命令、等待有重叠，不能相加。

已实现并实际检查独立修订保留路径及约束判断、恢复已验证内容后复用先前通过结果、保留中间失败尝试，以及证据压缩保留当前适用结果。未回答的用户决定不由修订自动清除。Scope 摘要由 Core 生成，不接受宿主自行盖章。
