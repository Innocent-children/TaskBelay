# 开发任务中的授权、验收与恢复

[中文](ENGINEERING-CONTROL.md) | [English](ENGINEERING-CONTROL_en.md)

## 解决的问题

长任务需要从实际结果继续，普通方法调整不应重复审批，已经完成的独立检查不应全部重跑。与此同时，接受旧回归失败不能代替本次需求验收，响应丢失不能触发不确定命令重放。Core 保持唯一 Task，代理负责理解需求和技术判断；没有固定开发节点或通用工作流。

## 请求与实施安排

authorization 保存真实 user_ref、请求、目标、明确限制和用户设置的投入上限。plan 保存 approach、verification_basis、checks、expected_paths 和 review_after_lines。预测路径不代表权限；允许/禁止路径、内容固定值和依赖限制由 Core 检查。

revise_task 按对象替换提供的 authorization 或 plan。方法、检查、预测及复核提示可以在原请求内调整；用户目标、明确限制或已有正数额度扩大/取消需要实际新决定。未受影响的进度和结果保留，累计投入不重置，修订不会自动回答未解决问题。Progress.NextStep 保存下一步；changes 保留最多 64 条近期决定和调整原因。

## 检查与验收

Check.GoalIDs 是检查到目标的唯一关联。每个目标至少一个 acceptance 检查；acceptance 和 regression 都需要解决，diagnostic 只辅助诊断。检查保存具体命令、输入、条件和理由，缩小输入范围须说明实际依赖；声明之外的文件、数据库或服务不视为已经检查。

相同条件下通过的结果复用，相关输入、要求或环境变化使对应结果失效。相同失败条件的重试需要新诊断信息；三次无变化失败后改变代码、条件或方法。完整套件须说明当前缺口。Core 能核对实际运行和适用条件，不能证明检查充分或代理解释正确。

已知失败例外仅用于 regression，要求真实失败、通过的比较检查和用户明确接受，且结果仍适用。交付的 acceptance 只引用通过的 acceptance 记录。目标已完成、必需检查已解决、改动复核完成且没有未确定执行或未解决决定时才能结束。claim 永不满足检查，human 仅记录实际用户观察。

## 工程问题与检查覆盖

Host 使用已有 goal_ids、rationale、conditions、verification_basis 说明每项检查覆盖的行为、主要失败路径和未覆盖范围。条件文字不自动执行断言；签名、接口或数据结构变化要核对真实调用方和相关测试能否构建。Core 核对目标关联、实际结果和适用条件，不通过模型评分判断检查充分性，也不增加固定检查阶段。

实际未解决问题保存为 assessment.concerns，每项有稳定 ID、原始描述及相关目标、检查、路径。省略或空数组保留原问题。verified 引用适用的真实通过结果；not_blocking 说明为何不妨碍当前目标，并形成交付限制；scope_changed 引用已经保存的真实用户范围变化。相关依赖变化需要重新处理。这些方式不能豁免必需检查、确定性违规或未知运行。最终 review 只提交 summary，不能靠清空一段 uncertainty 掩盖原问题。

## 原生执行与恢复

宿主原生进程工具以 JSON stdin 调用 Core check run。原生工具负责权限、环境、异步等待和信号，Core 负责持久预留、真实进程和结果收据；MCP/HTTP 不启动命令。长命令保留原生会话及运行身份，不通过拉长 MCP 请求或增加调度服务解决。

响应丢失先读取原 Task/run。已有收据恢复不执行命令；进程仍运行或无法确认时保持 pending。全部停止且收据缺失时核对副作用，需要用户决定时保存真实决定，结果仍为 interrupted_unknown。恢复不生成通过结果。完成、取消和归档不删除工作区或授权 Git 发布。

## 计量与额度

未设置上限时零值表示不限额，持续保留变更调用和实际执行的消耗。正数上限在执行与预留时检查；预算不足不降低验收标准。实际、预留、未知量分开，Core 与宿主时间有重叠，不能直接相加。

变更调用先完成计量准备，失败时不执行。保存状态查询不写计量、不查询进程身份，因此仍能读取恢复信息；累计 Core 时间不包含这些查询。宿主仅提交实际取得的累计 host_usage，按 Task 内不重叠 source_id 去重，使用 observed_through 和 coverage 说明来源及覆盖。未知为 null，测得零值为 0；部分报告不能称为完整用量。明确 Host 上限缺少报告时仅阻止新命令，读取和恢复不受影响。

## 用户界面

WebUI 提供搜索、宿主/状态筛选、语言选择、实际用户答复、失败例外和运行恢复。答复绑定当前 issue_digest 并保存原因，不自动改变明确限制。界面不自动重放变更；响应丢失后先刷新，已保存但显示刷新失败时明确区分，旧请求不能覆盖另一项任务。

checkpoint 可省略或原样重复提交当前 issue，但不能替换未解决的问题；须先用 resolve_issue 保存真实用户答复，再记录另一问题。

## 验收方式

在临时 Git 仓库和独立 SQLite 中检查：拒绝没有验收检查的目标；回归例外不替代验收；方法调整保留独立结果；用户答复不能绕过限制；保存状态查询在进程查询被拒时仍可使用且不写计量；MCP/HTTP 无法启动命令；原生命令中断恢复保留身份与投入；搜索筛选先于分页。浏览器核对决定、预算及未知运行结果回读，模拟响应丢失和过期页面请求。

统一验证入口包含 Go、前端、真实运行旅程、四宿主独立包、现有发布器和桌面构建检查。测试使用隔离资源，不执行公开发布。真实模型会话、其他平台原生运行和实际使用收益分别报告；脚本语义输入不冒充真实用户验证。旧数据保留且拒绝打开，不迁移或重置。
