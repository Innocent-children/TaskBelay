# 工程控制设计与验收

[中文](ENGINEERING-CONTROL.md) | [English](ENGINEERING-CONTROL_en.md)

## 用户问题与预期结果

用户希望 AI 在确认的需求内完成必要、适度、可验证的工作，避免过度设计、过度测试、顺手修复、验收降级和未授权操作。改动量或测试数量本身不能判定过度；必要的根因修复和职责调整必须能够继续。每项工作需要说明对应目标、不做的后果、责任归属及更直接方案的取舍。

## 数据与责任

Core 是唯一 Task 权威，保存授权、完整方案、具体版本的用户确认、实际观察、检查、证据、累计投入及结束条件。Host 展示方案、取得真实用户答复并进行有依据的语义判断；用户消息引用仍是宿主提供的审计信息，不能认证真实对话。repository 观察 Git 和文件事实，execution 执行明确 argv 并产生结果收据，store 提供原子更新、请求去重、目录占用和有界记录。CLI、MCP、HTTP 共用服务。

## 开发前确认

open_task 保存待确认方案：需求理解、根因、实施方式、更简单方案比较、工作项及责任、验证必要性和完成条件。plan_digest 同时绑定目标、约束、允许/禁止路径、依赖规则、检查定义、投入上限、工作区和提案时内容。confirm_plan 保存明确用户答复及对应摘要。确认前不允许实施写入、执行检查、提交工作进展或用户验收。提案后发生未确认改动时拒绝确认；恢复原内容或明确披露后修订方案。首次调查先使用宿主已授权的只读操作。

revise_task 更新授权、方案和检查；实质内容变化清除确认，必须展示修订后再取得答复。未变目标的进展与仍适用的执行证据可保留，累计费用不重置。checkpoint 只记录进展、语义审查、问题和宿主成本，拒绝 checks 成员。已有有效确认跨会话继续使用，不因普通进展反复询问。

批准保存原方案摘要、去除可同步配置后的授权摘要、额度上限和各检查超时上限。仅超时不超过既有批准、说明文字同步及各额度恢复到既有批准内可复用确认；目标、计划、路径、依赖、输入、命令、重试或完整套件语义变化不得复用。taskbelay_update_budget 要求当前方案摘要与完整具体预算的实际决定，统一更新 Core/宿主工作时间，并单独保留预算答复来源，不重置成本或代替验收。

## 范围与设计必要性

expected_paths 是预测；allowed_paths 是明确允许范围，缺省为已绑定仓库；forbidden_paths 优先于允许规则。多仓库具体路径使用 key::path，点号表示整体。结构化写入先检查方案批准、未解决授权问题、工作区身份、允许范围、禁止路径及固定内容。Shell 和外部编辑在观察时发现；插件不冒充全局沙箱。

每项实际路径判断关联计划 work_id、goal_ids、依据及必要性。Core 检查关联有效性及当前内容，不替代理证明语义正确。交付前还需绑定当前内容和方案的整体复核：根因、职责、复杂度、验证是否适度、重新设计是否仍会选择这个结构。未知项或否定结论不能放行。语义评分不能覆盖硬限制。

依赖许可使用具体仓库清单路径与包名。npm 的 dependencies/devDependencies/optionalDependencies/peerDependencies 前缀用于说明真实声明位置，不能当作包名的一部分误拒绝已允许的包。许可不授予其他仓库、禁止文件或安装操作的权限。

Host 和 Core 使用同一不可变来源选择：本地来源读取原 base_branch 的配置上游；远端来源读取指定 remote_name/base_branch 的追踪分支，不要求本地同名分支。任务分支自有上游不替代来源。整合另需真实授权与稳定 operation_id；私有原子收据在修改前保存整批意图与冻结目标，逐仓保存已应用、受阻或未知结果。多仓 Git 不是原子事务，后续漂移时保留已完成仓库并返回部分结果。同一身份只读原收据；恢复只核对停止所有者后的当前 Git 事实，不重放命令、继续剩余仓库或回退用户工作，未知命令结果仍为未知。

远端观察保存实际 fetch 完成时间 fetched_at、配置 remote_name/remote_ref、追踪提交和本地 HEAD；checked_at 是随后比较时间。失败或跳过不填写 fetched_at，不标为最新。Core 只核对本地事实；实际 fetch 仍由 Host 在真实 Git 授权下执行。

## 验证与防止重复投入

检查由已确认方案定义。purpose 区分 acceptance、regression、diagnostic；诊断检查也必须关联目标。每次运行提供 rationale，完整套件还需 full_suite_basis 说明定向检查不能覆盖的当前缺口。当前检查已有适用通过结果时应复用。仅改变超时、重试策略、完整套件标记或说明不使通过结果过期；检查重命名等使原结果不再适用时，不能仅因旧执行通过而禁止建立当前结果。相同失败条件重跑必须引用 previous_run_id 并提供新的 new_information；三次失败后必须改变真实输入、需求或验证方法。改检查名、理由或超时不清零同一执行条件的失败计数。

缺省 inputs 为所有已绑定仓库的 Git 可见内容。明确缩小范围必须有 input_basis；跨仓库依赖使用 key::path，可以包含显式声明的 ignored 文件。证据同时绑定检查、相关目标/约束、输入、环境和可执行文件。未掌握条件不视为已验证。失败仍保留失败来源；代理 claim 不能替代执行。预算是上限，剩余额度不是执行理由，耗尽也不能免除验收。

## 已知失败、恢复与交付

accept_known_failure 仅适用于方案中明确标为 regression 的检查，必须有当前真实失败结果、已批准比较检查的适用通过结果、明确列出的既有失败及用户接受决定。比较检查用 compares 指向被比较项；比较规则本身需要技术审查。不能豁免 acceptance 检查。例外绑定方案和内容，变化后过期；失败状态保持 failed。交付引用实际证据及有效例外，不能伪称全部检查通过。

运行前保存身份和预算预留，命令激活前保存受管进程身份；丢失响应读原结果，恢复收据不重跑。Core 退出后命令或进程组仍存活时继续保留未确定执行。全部停止后，无收据的执行记录为未知，不推断通过。未确定运行阻止新执行、完成和取消。累计执行、Core 调用及宿主报告投入在修订和压缩后保留。生命周期仅 active/done/cancelled；只有当前批准、必要性复核、所有目标与检查和未确定操作同时满足条件才能 done。取消保留文件并释放占用。终态可归档和取消归档，列表分页不再截断为前 200 项，详情链接直接定位任务。

## 风险与非目标

不做历史数据兼容、迁移或自动删除；不新增通用状态机、编码模型、安全沙箱、自动 Git 发布或跨工作区迁移。不能认证宿主语义判断或阻止未经过接入边界的动作。实际进程成功不证明检查充分，更不能证明净成本下降。控制自身也有开销，不应每次机械编辑都提交表单或查询状态。

## 验收方式与实施前评估

在隔离 Windows Git 仓库和 SQLite 中验证：确认前拒绝执行；旧确认不能批准新计划；普通检查点不能换掉失败验收；授权路径之外写入被拒绝或观察阻塞；跨仓库依赖变化使证据失效而独立证据保留；无理由重试及改名绕过被拒绝；例外保留失败且随内容过期；真实中断不重复执行；分页、归档和详情链接可用。

同时检查误拦：确认后的必要根因修复可进行，实现与验证可交替，未变内容可复用真实证据，用户明确接受的既有回归失败不伪装为通过。通过 Core、协议、存储、适配器及旅程测试分别记录，原生 Host 聊天与其他平台不以模拟代替。

该方案帮助跨会话恢复真实批准和结果，以 Git 与执行证据控制工作，保留一次必要的开发前确认；只有一个 Core Task，没有新增开发阶段表单。收益必须通过实际任务对照测量，不能由字段齐全或测试通过推断。检查入口见 [项目状态](PROJECT-STATUS.md)。
