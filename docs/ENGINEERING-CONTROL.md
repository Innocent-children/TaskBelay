# 开发过程中的授权、验证与恢复

[中文](ENGINEERING-CONTROL.md) | [English](ENGINEERING-CONTROL_en.md)

## 使用场景与处理原则

TaskBelay 用于需要保留进展、核对验证结果或跨会话继续的开发任务。用户给出需求和限制后，代理在已有授权内推进；小型机械修改、一般问答和无须保存进展的工作通常直接使用宿主即可。

原流程把用户授权、完整实施计划、每项检查和工作位置选择绑定在一起。正常调整实现、增加针对性检查也会触发重新确认，用户还要为默认成本额度作决定。本次调整将用户决定与代理的工作安排分开：保留实际请求、明确限制和累计消耗，删除重复确认及重复填写的计划内容。

## 授权与工作位置

open_task 使用真实用户请求的 user_ref、request、目标和明确限制。已有请求足以授权当前工作时直接开始，不另设方案确认工具。代理说明实施思路和验证依据；具体方法由代理在用户边界及宿主权限内选择。Core 不认证对话来源，也不授予任何宿主原本没有的权限。

默认沿用用户指定或当前已选定的工作区，展示目录、分支及已有修改。只有工作位置不清楚、存在冲突或确实需要新增分支/工作树时才处理相应决定。远端检查和整合按任务需要及真实 Git 授权执行，不是开工必经步骤；未检查的远端状态明确记为未知。

revise_task 只提交需要替换的 authorization、plan 或 checks，并说明原因。实现思路、检查方法、预测路径和复核提示调整沿用原请求。改变目标、请求、明确限制，或扩大已设成本上限，必须引用实际的新用户决定。旧请求不能为扩大范围背书。未受影响的目标进展、验证结果和累计消耗保留；相关输入、要求或执行条件变化使对应结果失效。

## 范围与必要性

计划只保存 approach 和 verification_basis。目标表达要完成的结果；路径判断用 goal_ids 和 basis 说明实际改动与目标的关系，不再重复建立工作项和必要性字段。交付复核用一段 summary 解释是否解决原问题、责任是否合适、复杂度与验证是否适度，以及是否仍会选择当前结构；uncertainty 记录尚未解决的问题。

expected_paths 只是预测。allowed_paths、forbidden_paths、固定内容和依赖限制表达实际用户边界；不得把预计会改的文件冒充用户禁止改动其他文件。结构化写入钩子检查明确范围和待解决授权问题。其他编辑在检查点观察；TaskBelay 不是沙箱。

## 验证与成本

检查保留实际 argv、输入、环境、目的和必要理由。代理可以在当前目标内调整检查，无需让用户审批每条测试命令，但必须遵守原生工具权限，不能以弱化检查冒充完成。新的方法必须取得自己的实际结果；claim 不满足验收，human 只记录真实用户观察。

通过结果在相同条件下复用；相关变化使其失效，无关目标或检查的增加不使独立结果失效。相同失败条件的重试须有新诊断信息；三次无变化失败后改变代码、条件或方法。完整测试套件要有当前必要性，不机械重复执行。

用户没有设置额度时，零值表示未设置上限，仍记录所有实际消耗。明确设置的正数上限会被执行；扩大或取消该上限需要实际用户决定。预算不足不会降低验收标准。实际、预留和未确定耗时分开；Core 和宿主时间存在重叠，不能直接相加。

## 中断与交付

运行前保存操作身份，执行结果保存后再返回。响应丢失先读取原 Task/run；恢复已有收据不重新执行。仍在运行时等待；执行已停止但结果无法确认时，核对副作用并保留未知结论，不把未知变成通过。

完成要求目标已有结论、必要检查有适用结果、当前改动已复核，并且没有未确定执行或待决定事项。已知回归失败可以通过真实比较和用户决定接受，失败仍显示为失败；相关检查或条件变化使该例外失效。取消、完成和归档保留文件，不自动提交、推送、合并或发布。

## 验收方式与范围

在临时 Git 仓库和独立数据库中验证：真实请求可直接开始；调整方案或检查无需再次确认；实际改变授权须有新用户引用；未设额度不会人为阻断；已设额度仍有效；需求变化和外部修改只使受影响结果失效；执行响应丢失和中断后可以恢复；缺少必要检查不能交付。同步验证工具 Schema、宿主安装包和界面。

覆盖正常流程、常见失败和已有相关问题，不为多个罕见条件叠加的假想场景增加机制。原生 Core 执行、脚本提供的用户/语义输入、宿主适配测试和真实模型会话分别记录。真实任务的质量、介入次数、时间和消耗需要对照测量；测试通过不证明产品收益。旧数据库保留且拒绝打开，不迁移或自动删除。
