# TaskBelay 文档国际化策略

[中文](I18N.md) | [English](I18N_en.md)

## 适用范围

本策略管理仓库中的人类可读文档，不定义产品运行时 locale。运行时行为仍以源码、机器可读
Schema、package manifest、CLI parser 和可执行测试为准。

## 维护语言

根 README 的内容发生变化时，9 种语言同步更新。详细文档继续维护英文和简体中文配对文件，包括：

- `docs/PRODUCT*`、`docs/DEMO*`、`docs/ROADMAP*`、`docs/PROJECT-STATUS*`；
- `docs/CORE-RESPONSES*`、`docs/ARCHITECTURE*`、`docs/COMMANDS*`、`docs/WEBUI*`、`docs/SUPPORT-MATRIX*`；
- `MANIFEST*`、`CONTRIBUTING*` 与本 I18n 策略；
- Codex、DeepSeek、Claude Code 和 ZCode 的中英文 Host 文档；Claude 对应 `docs/CLAUDE.md` 与 `docs/CLAUDE_en.md`，ZCode 对应 `docs/ZCODE.md` 与 `docs/ZCODE_en.md`。

简中/英文配对文档保持相同含义，并各自遵守该文档族的内容范围。

桌面使用与工具链策略也维护简中/英文配对。同步在各页职责内保持相同产品含义，详细字段通过技术参考链接提供。

## 同步范围

先按职责选择文档族，再同步翻译。根 README 负责项目介绍和日常使用，PRODUCT 负责产品范围与
行为规则，技术参考负责接口与实现细节。阅读入口见[文档目录](../MANIFEST.md)。仓库 AI 的工作
规则和文档更新范围统一维护在 [AGENTS.md](../AGENTS.md)。

1. 项目用途、主要能力、前置条件、安装、常用操作或必要使用限制变化时，更新根 README，
   并将受影响的内容同步到全部 9 种语言。
2. 内部实现、协议、测试、构建或 AI 工作规则变化，本身不要求修改 README；翻译更新留在
   负责相应内容的文档族中。
3. PRODUCT 或技术参考中的表述变化时，同步其维护中的简中/英文配对文件，不为同步文档而
   将内容复制到其他文档族。
4. 在 Pull Request 验证说明中列出实际更新的文档路径和语言。

翻译保持能力、命令、selector、package 名、路径、版本身份和支持声明一致，不增加对应简中
或英文内容中不存在的能力和平台承诺。

## 安装命令与版本身份

面向普通用户的安装示例使用 npm 稳定 channel：

```text
taskbelay@latest
taskbelay-codex@latest
taskbelay-deepseek@latest
```

Core、Codex、DeepSeek、Claude、ZCode 和 TaskBelay CLI 的精确产品版本只保存在机器可读版本文件、package metadata、
Release Tag、构建产物 digest 和发布记录中。人类文档不写入精确产品版本。

命令说明必须对照实际实现：

- package 名称、`bin` 和平台约束来自对应 `package.json`；
- Codex 命令来自 `packages/codex/bin/taskbelay-codex.mjs`；
- ZCode 命令来自 `packages/zcode/bin/taskbelay-zcode.mjs`；
- 统一 lifecycle 命令来自 `packages/taskbelay/lib/cli.mjs`；
- DeepSeek 安装与移除形态来自 DSH lifecycle tests；
- packaged Core 命令来自 `cmd/taskbelay/main.go`；
- MCP 工具来自 `internal/mcp/` 的固定工具列表。

## 翻译不变量

所有 locale 必须保持以下内容一致：

- TaskBelay 的主要定位和首要失效场景；
- 当前能力与未来方向的区别；
- 命令、selector、工具名、环境变量、路径和文件名；
- package、bundled Core、平台与 Host 兼容范围；
- 能力、非目标、安全边界和支持声明的含义；
- 指向当前简中/英文技术参考的链接。

叙述可以按目标语言自然表达。没有稳定译法的标识符保留英文，不为不同语言发明额外产品术语或
承诺。

## 审查要求

按受影响的文档族检查：

- 语言导航中的所有文件存在；
- 修改 README 时，9 种语言表达相同的项目介绍、安装、操作、必要限制和文档入口；
- 简中和英文技术文档族表达同一产品事实；
- 所有普通安装示例使用 `@latest`；
- 非英文文件没有占位翻译或整段英文 fallback；
- 修改的命令说明与当前 parser、lifecycle tests 和 MCP catalog 一致。

工程设计与验收同样维护 docs/ENGINEERING-CONTROL.md 和 docs/ENGINEERING-CONTROL_en.md，保持行为规则与验证边界一致。
