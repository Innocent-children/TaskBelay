# 本机 WebUI

[中文](WEBUI.md) | [English](WEBUI_en.md)

配置适配器后运行 taskbelay webui start；status 查询实例，open 打开实例，stop 停止界面服务。列表支持需求/任务 ID 搜索、宿主和状态筛选、归档显示和分页，所有过滤在分页前完成。语言选择保存在浏览器；/tasks/{id} 可直接打开任务。

桌面采用紧凑任务列表与详情双栏，列表展示需求摘要、仓库简称、宿主和状态；完整需求和目录在详情中查看。搜索与筛选保留在任务切换之间。窄屏分别展示列表和详情，返回列表保留筛选与位置。

详情分为“概览”“检查记录”“需求与投入”。概览优先展示用户待决定问题、未确定执行、当前结果、目标进展和剩余问题；没有剩余问题时不显示空白区域。检查按条目展示实际结果和适用情况，输出在对应条目下展开。需求、计划、工作位置、明确限制、检查定义、累计投入和近期调整在各自区域查看。

“更新记录”只读取保存内容；“核对当前代码”重新观察代码和执行条件。界面分别显示保存更新时间、记录读取时间和本次页面内的核对时间。进行中任务在页面可见且没有正在编辑的表单时定期读取保存记录；答复或运行结果不明时须由用户主动更新记录。读取保存状态不写计量或查询进程身份，任务进行中不表示代理此刻正在执行。

后台读取发现任务修订与需求、内容、计划摘要全部未变时，保留上次由 Core 返回的核对结果及时间；这不构成新的代码核对。记录发生变化时展示新记录，用户主动“更新记录”也会切换到保存内容。

用户可直接答复当前问题，答复绑定 issue_digest 并进入近期决定记录；它不自动修改授权范围。预算调整展示实际变化并保留已有消耗。人工检查只用于用户确实完成的检查。接受旧回归失败须选择当前失败运行、通过的比较运行，列出失败内容并说明原因；本次需求验收仍须通过。

恢复先读取原运行，可以恢复已有结果；原进程仍运行或无法核对时拒绝恢复。结果缺失时，用户说明核对过的副作用和未知项，记录仍为未知，不重跑命令。网页不能启动检查进程，命令通过宿主原生工具执行。

答复、人工检查、预算调整、恢复和取消使用带上下文的表单，显示保存进度和具体失败信息，失败后保留输入。界面不自动重试变更。响应丢失先更新保存记录，已保存但刷新失败会明确说明；切换任务后旧响应不能覆盖当前任务。取消保留文件，未确定执行须先处理；终态支持归档与取消归档。近期调整和用户答复可展开查看。

HTTP 仅绑定 loopback，变更受 Host、Origin、CSRF 检查。界面不拥有第二份任务状态。源码检查、浏览器交互和真实宿主会话分别验证。见[命令](COMMANDS.md)和[产品](PRODUCT.md)。
