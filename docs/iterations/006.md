**如何复核范围。** 在 macOS arm64、Go 1.27.2 上，临时探针只使用标准库。两个夹具是载体，取的是内嵌源码，不是载体自己的 Go 导入块。对前者使用 `parser.ParseFile(fset, path, data, parser.SkipObjectResolution)`，其中 `data` 是校验过的完整原文。只取 `file.Decls` 中 `*ast.GenDecl` 且 `Tok == token.IMPORT` 的节点；以同一 `token.File` 的 `Offset(Pos())`、`Offset(End())` 切回原字节，以 `PositionFor(pos, false)` 核对物理行列。标准库 `go/ast/ast.go` 中，分组声明的起点是声明关键字，终点是 `Rparen + 1`；只取各项 `ImportSpec` 会漏掉块首和右括号。

**证据何时可用。** 范围只对解析时的路径和 blob 有效。若将来使用，只能核对同一快照原字节上的单元；路径相同而 blob 不同，不能沿用。缩进单元的末尾可能含换行或空行（见 `internal/units/layout.go` 的 `indentLayout`），所以不能以行号重叠排除整单元。应能证明单元内的代码完全落在已确认的声明范围；混有范围外的代码就保留原判断。不支持该语言、解析报错（即使返回部分语法树）、输入版本或区间无法核对、解析未完成时，都不提供可用于排除的范围。原来应报的未知继续保留，失败或未完成也不能算通过。

## 结论与接续

**Go 原样本有可靠来源，现有语言无关输入本身没有提供这项证据。** 证据来自 Go 语法；Python 调用得以保留，是因为来源不支持该语言、不能据此排除调用，并非该来源识别了 Python 测试。

若随 Go 二进制编入标准库解析器，用户端无需安装 Go、下载被导入的包或启动额外进程。代价是增加二进制所含代码，每个待解析的文件还要读取同版字节、解析并在内存中构造语法树；本轮未测增量体积、耗时或内存。语法支持取决于编入的 Go 工具链版本。本次只验证了 macOS arm64；所用 API 不依赖该系统，Windows、Linux 未实测。

`docs/algorithm.md` 和 `docs/languages.md` 规定语言知识来自仓库、扩展名只用于分组。即使内核只消费路径、blob 和字节范围，选择 Go 文件、调用 Go 解析器并解释导入节点仍是语言适配。若要采用，需先决定是否允许在输入侧引入这种可选的语言语法证据，并接受各语言覆盖不对等；把它移到内核外不会自动满足现约束。若维持原约束，原 Go 样本仍按未知处理。本轮仅交付可行性依据，产品与运行版未变，未决定采用，实际减少误报或节省 Agent 工作的效果未验证。
