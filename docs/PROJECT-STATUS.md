# TaskBelay 项目状态

[中文](PROJECT-STATUS.md) | [English](PROJECT-STATUS_en.md)

当前源码支持在已有用户请求下开发和验证，保留唯一 Core Task、实际运行结果、未解决问题和累计投入。方法、检查与普通工作安排可以按实际情况调整；改变用户目标、明确限制或扩大已设上限仍需要真实决定。公开 npm 版本、Tag、发布记录和平台支持承诺没有随本次源码改动更新。

## 当前实现

- 工程问题按稳定 ID 保存在 assessment.concerns，明确处理后才能消除对应完成缺口。交付限制由适用的 not_blocking 处理记录生成；省略文字、空数组或完成说明不能删除原问题。
- Decision.gaps 统一说明未满足的目标、检查、审查、问题和运行。失败返回当前身份、已有结果及已知提交/执行情况；恢复不重跑原命令。
- 使用已有 goal_ids、rationale、conditions、verification_basis 表达检查覆盖，保留适用的独立结果。通过的命令只执行一次；未知用量或额度用满都不能把已完成结果变成再次执行的理由。
- 在有意义的新开发或恢复时寻找实际 Task；多个目录的预检返回全部已有身份。Host 保留实际权限和消息来源，不维护第二个任务游标。
- 普通变更返回紧凑状态；context、详情、实际输出与完整方法契约按需读取。100 个现有接口/操作分支具有输入输出说明和成功/失败样例，随包帮助可在没有源码和数据库时读取。ZCode 使用简短 MCP 文本，其他主要展示文本的 Host 保留完整文本。
- 新分支显式使用 --no-track，原始来源与 Task 上游分开。Host 用量按非重叠来源累计采样，在同一 CAS 事务中去重、更新总量和保存操作；未知与零值分开显示。

当前数据库只接受一个 Schema。旧数据保留且拒绝按新布局打开，不迁移或重置；试用源码需要独立数据目录。当前 Core/Schema 版本以 CORE_VERSION 与 internal/store 的定义为准。
