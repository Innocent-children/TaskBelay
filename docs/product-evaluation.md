# 算法评估

## 当前仓库的测试维护范围

本仓库长期只保留打包、安装及必要安装维护的基础测试，包括发布元数据、版本比较、校验与替换、接入配置和用户数据保留。模块修改需要验证时，依据本次确认的需求和当前实现重新编写必要的临时测试；通过后删除测试代码、专用辅助代码、样例和临时产物，在当次交付回复中说明验证范围、环境、命令与结论，不保留项目内验证归档。意图明确、可直接阅读推演的改动不为走流程新增测试。

旧测试不能直接作为当前需求，其他模块测试、端到端数据集和评估脚本不作为常驻资产维护。产品自身的测试分析、运行和验证记录功能继续保留。

下文是 [目标算法](algorithm.md) 的评估设计，尚无新算法运行结果。它不构成执行任务、固定回归矩阵或自动恢复历史资料的授权。实际验证按当前请求及改动影响选择，文档变更只做必要的阅读、引用与一致性核对。

## 要回答的问题

评估同时回答四件事：统一表示和仓库统计是否如实，核心算法是否满足各自的性质，是否减少实际多余工作，以及总成本是否值得。理论复杂度、临时验证和真实 Agent 效果分别报告，不能相互替代。

| 层次 | 核对内容 | 不能据此推出 |
| --- | --- | --- |
| 输入与统计 | 词法、版面树、学到的约定、种子匹配和命令归类是否正确 | 统计结果合理不等于需求理解正确 |
| 算法 | 变更簇、需求相关区、分组检验、集合覆盖、验证输入等是否满足各自的性质 | 算法性质成立不等于实际效果好 |
| 接入与流程 | 实际事件、身份、结果、授权和用户修改是否正确处理 | 构造事件通过不等于真实 Agent 已接入 |
| 端到端效果 | 交付行为、多余工作、误判和总成本的变化 | 减少代码或命令数量不等于效果更好 |

## 核心性质与边界

需要专项验证时，在临时目录围绕本次变化构造有限输入及可核对的预期，不恢复固定语言规则全集。以下性质用于选择验证范围，不要求每次全部执行。

| 对象 | 关键性质与反例 |
| --- | --- |
| 统一词法与版面 | 同一 blob 的分析结果不变；括号树与缩进树的选择稳定；二进制内容按整体记录 |
| 仓库统计 | 扩展名一致改名后统计结果对应不变；样本少时结构置信度降低 |
| 变更簇 | 撤回一个簇连同依赖它的簇时不留下悬空引用；构建失败时合并后重算；混合来源不成为候选 |
| 需求相关区 | 常见词不传递关联；只经公共函数相连的顺手改动落在相关区外；没有种子时为未知 |
| 对外新增项 | 只比对名字和取值，说明文字不参与；登记为实现位置的项属于 Agent 锚定；只按形状识别、未经探针确认的项不拦截；Agent 锚定和保留下来的未锚定项出现在交付报告中 |
| 间接层与近似重复 | 名义类型和结构类型的实现都能计数；调用写法比例低时参数分析为未知 |
| 撤回试验 | 只撤回 Agent 变更簇；相关区内的簇只在对应需求有自己的验收依据时作候选；防御性短分支不作候选；最终撤回集合经过确认运行 |
| 分组检验 | d 小时运行次数与 d·log₂(n/d) 同阶，d 接近 n 时接近逐个运行；撤回补丁就是确认运行的那一组；确认失败后逐个加入得到的集合能通过 |
| 变异与约简 | 每个变异单独运行；无效变异不计发现；Good–Turing 按发现集合计数；冗余变异和贪心覆盖正确；保留集合中的用例不成为候选；删去候选后保留的用例全部通过 |
| 验证输入 | 未被引用的文档变化不改变验证输入；通过注释、目录或通配符引用的文档变化会改变验证输入；注释敏感和不稳定的命令不复用；范围包含、通过规律和注释不敏感只提示；两次运行之间修改过环境变量、结果未知、会写入、用户要求重跑时放行 |
| 合并与校准 | 相关信号一起拟合，不重复计数；标签按实际处理和恢复记录；不成立增多的类别排序下降；拦截只依据事实条件，与可信度无关 |
| 用户内容 | 混合片段不整段撤回；新快照发布后旧建议失效；工作区更新不新增授权 |
| 有限反馈 | 同一问题移动或修改其他文件不重置拦截身份，未知不构成拦截理由 |

对复杂度的核对记录实际规模：变化的字节数、变更簇数、推送工作量与相关区大小、LSH 候选数、分组检验的候选数与实际运行次数、变异数与发现矩阵大小。小例子符合理论界只能辅助检查实现；经典界依赖文档列出的前提，不能靠样本代替证明。

## 普适性

核心用一致改名检验：把整个仓库中的某个扩展名一致地换成另一个，或把工具名一致地改名，统计重新分组，结果应与原来相同，同分按稳定规则排序。这只证明算法没有语言分支。

真实项目另外按文本结构的性质选择样本：括号结构、缩进结构、配置驱动、生成内容、脚本入口、多语言混合，以及不同的命令输出格式。分别统计学到的约定是否正确、结构置信度是否反映实际的可靠程度，以及低置信度文件上的结论是否变少而不是变错。

## 正常开发与接续

选择与本次影响直接相关的流程，按有序事件、实际文件和账本版本核对：

| 场景 | 验收 |
| --- | --- |
| 多次提交、部分暂存、amend | 起点不变，累计改动完整，实际索引不被改写 |
| 用户修改、删除、移动或改名后继续 | 使用当前内容，保留用户行为，位置无法对应时保留未知 |
| 两个 session 并发编辑或更新需求 | 不覆盖较新记录，旧输入结果只保存为历史 |
| 切分支、stash、pull、rebase、暂停恢复 | 工作区更新与 Agent 编辑分开，任务和有效决定连续 |
| 追加、撤销需求或用户保留决定 | 相关区与信号重新计算，旧授权不再支撑当前行为 |
| 半自动范围内调整及待确认增补 | 范围内照常开发，仅新增未授权部分等待；精简建议不新增审批 |
| task_finish 后输入未变或已变化 | 分别处理原交付请求或过期请求，不循环强制验证 |
| 跨 Agent、压缩或隔天接续 | 有效结果可复用，未知范围不消失，旧下一步不成为必须重跑的指令 |
| 动态检查期间用户编辑 | 不锁工作区，旧结果不用于当前拦截，不自动反复重跑 |
| 结果字段缺失、超时或接入错误 | 记录真实完成程度，TaskBelay 自身故障不阻断正常工作 |

涉及平台、shell 和 Agent 时，注明实际环境、版本与取得的观察；交叉编译、内部模型和构造事件分别只证明各自范围。Windows、macOS、Linux 及两个 Agent 的结论不能互相推定。

## 端到端对比

开展已授权的专项评估时，先确定任务范围、成功行为、比较方案和停止条件。任务既包含确有多余设计或重复验证的情况，也包含应保留抽象、广泛回归或随机采样的情况；不能只选容易精简的任务。

以同一需求、起点和运行环境比较关闭与开启 TaskBelay。固定并记录 Agent、模型、工具及设置，动态检查开关分别报告。行为验收依据由独立来源确定，核对新增失败和实际保留行为，不用当前算法的分数充当唯一标准。

样本量与重复次数按问题、成本和统计不确定性确定，不沿用“三十个 PR、每个三次”等固定矩阵。随机性需要重复时，预先说明假设、采样方式和上限；不能看到有利结果就停止，或为追求显著性无限追加。历史对照只有条件可比才可复用，否则保留差异。

运行前确认 hook 实际参与；缺失、超时或不完整结果保留在样本中并单列接入失败率，不能删除失败样本后报告效果。出现行为退步先查清相关结论的依据与实际原因，再决定是否需要追加能够回答该问题的验证。

## 指标与采用条件

| 指标 | 解释 |
| --- | --- |
| 正确性 | 当前需求、直接相关的既有行为及用户修改是否保留；新增失败逐项报告 |
| 精简收益 | 确认多余的改动被减少多少，维护成本哪些方面改善或恶化 |
| 无效验证 | 不提供新信息的验证运行及其成本减少多少；必要验证是否被错误阻止 |
| 错误拦截 | 被拦截的改动和验证中实际必要的比例、数量与原因 |
| 建议质量 | 建议采纳后是否保持行为、减少负担；采纳本身不等于建议正确 |
| 漏判 | 抽查放行和未提示的情况，核对仍存在的多余工作 |
| 依据质量 | 种子匹配和锚定错误、学到的约定错误、过期结果误用及未知范围 |
| 使用连续性 | 用户修改保留、任务接续、重复提示与额外审批次数 |
| 总成本 | Agent 与 TaskBelay 合计墙钟时间、模型 token、命令、资源和用户处理时间 |

代码行数、用例数、验证次数可作为辅助数据，不设必须下降的比例。不能通过删除必要测试、全部放行或让用户反复解释需求改善表面指标。分别报告两个 Agent、动态开关及实际平台；某一组收益不能抵消另一组正确性退步。

采用结论必须同时说明正确性、误判与漏判、精简收益和成本。报告样本数、分布和不确定性；依据不足时结论保持未定。校准之外的参数调整依据具体错误，不为迎合历史断言更改需求。

## 性能与退化

记录词法与统计、变更簇、相关区推送、静态信号、合并与选择、副本运行、序列化和发布的成本。文件观察、Git 和环境核对都进入总量；缓存命中也有核对成本，不能只报告内核循环耗时。

分别观察冷启动、无变化复用、局部变化、起点 tree 变化导致的统计更新，以及候选很多而静态信号不准（分组检验接近逐个运行）的场景。关注中位数、P95、峰值内存、完成比例和未知范围，避免通过提前放弃分析获得看似更快的结果。

核对预算到期时已停止相关工作、保存有效局部结果和未完成范围，用户仍能继续开发。预算是等待上限，不是性能实测或强制运行时长；理论复杂度见 [算法核心](algorithm.md)。

## 真实使用反馈

已有 `taskbelay hits --since 14d` 可提供问题、拦截和后续处理线索，但旧字段不能推导新算法未采集的信号与成本。目标设计的校准标签也可用于复盘，它们是产品运行中的统计，不代替专项评估中的人工核对。需要复盘时，同时抽查拦截、建议和放行，核对来源、条件与当前需求。

不因本文件自动建立周期性评估、持久数据集或新查询功能。每次明确授权的调整只验证能够回答该问题的范围，结果在当次交付中如实说明。
