# 算法评估

## 测试维护范围

本仓库长期只保留打包、安装及必要安装维护的基础测试，包括发布元数据、版本比较、校验与替换、接入配置和用户数据保留。模块修改需要验证时，依据本次确认的需求和当前实现重新编写必要的临时测试；通过后删除测试代码、专用辅助代码、样例和临时产物，在当次交付回复中说明验证范围、环境、命令与结论，不保留项目内验证归档。意图明确、可直接阅读推演的改动不为走流程新增测试。

旧测试不能直接作为当前需求，其他模块测试、端到端数据集和评估脚本不作为常驻资产维护。产品自身的证据分析、验证选择和记录功能继续保留。

下文是 [算法设计](algorithm.md) 的评估设计，尚无新算法运行结果。它不构成执行任务、固定回归矩阵或自动恢复历史资料的授权。实际验证按当前请求及改动影响选择，文档变更只做必要的阅读、引用与一致性核对。

## 要回答的问题

评估同时回答四件事：语义与证据是否可信，算法实现是否符合模型，是否减少实际多余工作，以及总成本是否值得。理论复杂度、临时模型验证和真实 Agent 效果分别报告，不能相互替代。

| 层次 | 核对内容 | 不能据此推出 |
| --- | --- | --- |
| 输入与语义 | 来源、版本、关系、作用范围、未知依赖是否正确 | 引用存在不等于解释正确 |
| 模型与算法 | 增量推导、约束解、覆盖选择及其前提是否成立 | 模型内最优不等于所有实现方案中的最优 |
| 接入与流程 | 实际事件、身份、结果、授权和用户修改是否正确处理 | 构造事件通过不等于真实 Agent 已接入 |
| 端到端效果 | 交付行为、多余工作、误判和总成本的变化 | 减少代码或命令数量不等于效果更好 |

## 算法正确性

需要专项验证时，在临时目录围绕本次变化构造有限输入及可核对预期，不恢复固定语言规则全集。以下性质用于选择验证范围，不要求每次全部执行。

| 对象 | 关键性质与反例 |
| --- | --- |
| 支持超图 | AND 前提缺一不可，OR 替代支持仍有效；仅有循环而无有效根时结论应撤回 |
| 增量维护 | 固定输入模型下的增量结果与完整重推导一致；删除、授权撤销、重新加入与并发版本变化分别核对 |
| 可能依赖 | 新增文件、缺失配置出现、目录枚举及外部状态变化触发相关失效；候选列表不完整时，不能据此认定依赖已全部确定 |
| 设计求解 | 小型有限模型可穷举核对可行解、成本与上下界；共享约束不得拆成独立分量 |
| 树分解 | 每个变量的袋连通、每个因子的作用域被袋包含；结构或边界变化不能误用旧表 |
| 有界搜索 | 超时报告已有可行解和未定状态；没有找到替代不能报告不存在替代 |
| 集合覆盖 | 覆盖关联、成本与贪心更新正确；问题集合为空、存在无法覆盖的问题、共同准备和顺序约束分别处理 |
| 运行后更新 | 计划覆盖不代替结果；失败、未启动和缺失输出不能移除尚未回答的问题 |
| 重复验证 | 未知结果、外部状态不明、产物缺失、必要副作用、明确重跑和随机采样应放行 |
| 语义判断 | 同名引用、单实现接口、相同行覆盖及同变异集合均不能独立支撑删除 |
| 用户内容 | 混合片段不能整段删除；新快照发布后旧建议失效；工作区更新不新增授权 |
| 提示与拦截次数 | 同一问题移动或修改其他文件不重置拦截身份，未知不构成拦截理由 |

对复杂度的核对记录实际规模：图节点与关联、受影响闭包、约束分量与树宽、重算袋数、操作数及覆盖关联数。验证某些小例子符合近似界，只能辅助检查实现；经典界仍依赖文档列出的假设，不能靠样本替代证明。

## 不同语言与工具下的一致性

对判定逻辑进行同构输入检验：保持事实、约束、依赖、成本和操作含义不变，只改变语言标签、文件后缀及工具名称，结果与证据应同构。同分选择按稳定规则比较，不要求改名后的显示文本逐字相同。

真实项目另外按行为性质选择样本，例如静态或动态调用、配置驱动、生成内容、脚本入口、多语言边界及不同执行环境。统计事实提取完整率、语义关系错误和未知范围，不能仅凭“能够解析某语言”就认定算法具有普适性。

同构检验通过只能说明判定逻辑没有按语言分支处理。实际输入是否准确，仍取决于信息采集和语义复核；缺少哪些信息必须明确记录，不能把缺少事实当作否定事实。

## 正常开发与接续

选择与本次影响直接相关的流程，按有序事件、实际文件和账本版本核对：

| 场景 | 验收 |
| --- | --- |
| 多次提交、部分暂存、amend | 起点不变，累计改动完整，实际索引不被改写 |
| 用户修改、删除、移动或改名后继续 | 使用当前内容，保留用户行为，位置无法对应时保留未知 |
| 两个 session 并发编辑或更新需求 | 不覆盖较新记录，旧输入结果只保存为历史 |
| 切分支、stash、pull、rebase、暂停恢复 | 工作区更新与 Agent 编辑分开，任务和有效决定连续 |
| 追加、撤销需求或用户保留决定 | 相关约束与证据失效，旧授权不再支撑当前行为 |
| 半自动范围内调整及待确认增补 | 范围内照常开发，仅新增未授权部分等待；求解候选不新增审批 |
| task_finish 后输入未变或已变化 | 分别处理原交付请求或过期请求，不循环强制验证 |
| 跨 Agent、压缩或隔天接续 | 有效证据可复用，未知范围不消失，旧下一步不成为必须重跑的指令 |
| 动态检查期间用户编辑 | 不锁工作区，旧结果不用于当前拦截，不自动反复重跑 |
| 结果字段缺失、超时或接入错误 | 记录真实完成程度，TaskBelay 自身故障不阻断正常工作 |

涉及平台、shell 和 Agent 时，注明实际环境、版本与取得的观察；交叉编译、内部模型和构造事件分别只证明各自范围。Windows、macOS、Linux 及两个 Agent 的结论不能互相推定。

## 端到端对比

开展已授权的专项评估时，先确定任务范围、成功行为、比较方案和停止条件。任务既包含确有多余设计或重复验证的情况，也包含应保留抽象、广泛回归或随机采样的情况；不能只选容易精简的任务。

以同一需求、起点和运行环境比较关闭与开启 TaskBelay。固定并记录 Agent、模型、工具及设置，动态检查开关分别报告。行为验收依据由独立来源确定，核对新增失败和实际保留行为，不用当前算法的分数充当唯一标准。

样本量与重复次数按问题、成本和统计不确定性确定，不沿用“三十个 PR、每个三次”等固定矩阵。随机性需要重复时，预先说明假设、采样方式和上限；不能看到有利结果就停止，或为追求显著性无限追加。历史对照只有条件可比才可复用，否则保留差异。

运行前确认 hook 实际参与；缺失、超时或不完整结果保留在样本中并单列接入失败率，不能删除失败样本后报告效果。出现行为退步先定位证据与实际原因，再决定是否需要追加能够回答该问题的验证。

## 指标与采用条件

| 指标 | 解释 |
| --- | --- |
| 正确性 | 当前需求、直接相关的既有行为及用户修改是否保留；新增失败逐项报告 |
| 精简收益 | 有依据的多余机制被减少多少，维护成本哪些维度改善或恶化 |
| 无效验证 | 无新增信息的操作及其成本减少多少；必要验证是否被错误阻止 |
| 错误拦截 | 被拦操作中实际必要的比例、数量与原因 |
| 建议质量 | 建议采纳后是否保持行为、减少负担；采纳本身不等于建议正确 |
| 漏判 | 抽查放行和未提示的情况，核对仍存在的多余工作 |
| 证据质量 | 语义关系错误、输入完整性、过期证据误用及尚无法回答的问题数量 |
| 使用连续性 | 用户修改保留、任务接续、重复提示与额外审批次数 |
| 总成本 | Agent 与 TaskBelay 合计墙钟时间、模型 token、命令、资源和用户处理时间 |

代码行数、用例数、验证次数可作为辅助数据，不设必须下降的比例。不能通过删除必要测试、全部放行或让用户反复解释需求改善表面指标。分别报告两个 Agent、动态开关及实际平台；某一组收益不能抵消另一组正确性退步。

采用结论必须同时说明正确性、误判与漏判、精简收益和成本。报告样本数、分布和不确定性；证据不足时结论保持未定。阈值和权重调整依据具体错误，不为迎合历史断言更改需求。

## 运行成本与性能

记录采集、语义提取、图维护、分解与求解、操作选择、实际执行、序列化和发布的成本。模型调用、文件观察、Git 和环境核对都进入总量；缓存命中也有核对成本，不能只报告算法计算耗时。

分别观察冷启动、无变化复用、局部变化、广泛依赖变化、稀疏低树宽和稠密高树宽场景。关注中位数、P95、峰值内存、完成比例和未知范围，避免通过提前放弃分析获得看似更快的结果。

核对预算到期时已停止相关工作、保存有效局部结果和未完成范围，用户仍能继续开发。预算是等待上限，不是性能实测或强制运行时长；理论复杂度见 [算法设计](algorithm.md)。

## 真实使用反馈

已有 `taskbelay hits --since 14d` 可提供问题、拦截和后续处理线索，但旧字段不能推导新算法未采集的证据与成本。需要复盘时，同时抽查拦截、建议和放行，核对来源、条件与当前需求。

不因本文件自动建立周期性评估、持久数据集或新查询功能。每次明确授权的调整只验证能够回答该问题的范围，结果在当次交付中如实说明。
