# 任务账本

账本保存任务目标、开发过程和交付结果。两个 Agent 的 hook 和 MCP 进程共用同一个 SQLite 文件。术语和行为由 [任务和需求](requirements.md)、两份判定文档、[半自动模式](semi-auto.md) 和 [任务接续](handoff.md) 定义。

## 谁写什么

| 记录 | 写入方 | 时机 |
| --- | --- | --- |
| 用户消息、session 和 hook 活动 | TaskBelay | 事件到达 |
| 需求、实现位置、决定和下一步 | Agent | 分析、开发和接续 |
| 方案正文、范围及确认来源 | Agent 提交，TaskBelay 核对并保存 | 提交和确认方案 |
| 观察点、Agent 编辑、工作区更新 | TaskBelay | 观察文件及核对编辑前后 |
| 验证与检查 | TaskBelay | 命令运行、检查和交付 |
| 任务切换及交付状态 | TaskBelay | Agent 请求开始、恢复和交付 |

Agent 通过 MCP 写自己的记录，用户消息和工具观察保留原始内容。更新需求、方案和决定时追加修订，原记录可供接续和报告查询。

## 记录和字段

### 工作区与设置

工作区记录仓库与 worktree 身份、当前路径、分支、HEAD、当前任务和最新观察点。路径变化后更新位置，保留同一身份。任务可以按分支恢复，分支名只是上下文，不作为代码来源的证据。

设置保存用户默认值、项目覆盖值和任务覆盖值。同一个本地仓库的 worktree 共用项目设置，各任务分别覆盖。包括 `workflow`、`enforcement`、动态检查开关、测试命令及准备方式、可并行条件。解析后的有效设置带修订号。

### 设置项

| 设置项 | 值和默认值 |
| --- | --- |
| `workflow` | `auto` 或 `semi`，默认 auto |
| `enforcement` | `block` 或 `hint`，默认 block |
| `analysis.tests` | `on` 或 `off`，默认 off |
| `test.<语言>.command` | 项目现有的测试命令或前缀，默认采用语言 Runner 的方式 |
| `test.<语言>.prepare` | 临时副本中的准备命令，默认无 |
| `test.<语言>.parallel` | 一至四，默认一；大于一表示这些测试可独立运行 |

命令按对应平台的 shell 解析，动态阶段开启后才执行准备和测试。CLI 用 `config set <设置项> <值>` 保存用户默认值，`--project`、`--task` 保存更具体的范围。当前会话中的明确要求由 Agent 记入任务决定，不要求用户另行编辑设置。

### 任务

| 字段 | 含义 |
| --- | --- |
| 编号、标题、工作区 | 全局唯一编号，形如 t17 |
| 状态 | 进行中、待交付、已暂停、已完成、已中止 |
| 起点消息、起点快照 | 原始任务起点，提交和暂停不改变它 |
| 上下文和恢复观察点 | 分支、HEAD、上次恢复时工作区状态 |
| 工作模式、设置修订 | 当前任务的有效设置 |
| 需求修订、方案修订、记录修订 | 检查和接续使用的版本 |
| 交付请求 | 请求者、轮次、请求时状态和本轮任务编号 |
| 创建、更新、暂停及结束时间 | 生命周期时间 |

`task_start` 切换任务的操作在同一个事务里完成：暂停当前任务，选中或建立目标任务，保存恢复观察点。

### 用户消息和需求

消息保存编号、原文、时间、Agent、session、轮次、到达时的上下文和工作区状态。引用保存消息编号与原文范围；已确认方案和项目约定也保存来源编号。

需求保存 R 编号、内容、验收标准、状态、原话来源、类型、实现位置、用途说明、修订号和修改者。状态为未开始、进行中、已完成、已撤销。每次更新保留之前版本；新要求撤回的决定标为失效。

实现位置保存种类、当前定位、编辑前定位、变更类型、引用和用途。移动、改名时更新当前定位；删除位置仍能在起点或编辑记录中读取。

### 方案

每版保存正文文件路径、完整范围清单、新入口和依赖、变更摘要、提交者、提交时间及观察点。确认保存版本、完整用户消息、引用范围、授权时间和授权方式。

有效方案包括已确认范围与仍有效的后续授权；待确认增补单独记录。新版本完整保存授权范围，旧版确认历史保留。每次提交、确认、撤回或范围调整都增加方案修订号。

### 观察与编辑

| 记录 | 字段 |
| --- | --- |
| 观察点 | 时间、触发事件、上下文、完整 tree 或目标文件的内容标识 |
| Agent 编辑 | 工具调用编号、请求路径、编辑前内容、请求中的改动、编辑后内容、核对结果 |
| 工作区更新 | 前后观察点、文件和片段、首次观察时间、与需求位置的联系 |

内容使用快照或 blob 标识引用。只有请求中的改动能与实际前后内容对应时，才记为可核对的 Agent 编辑。整个 shell 调用前后有差异，只能证明期间发生变化，不能据此把差异全部归给 Agent。

观察、编辑和需求修订组合成检查输入。相同声明里有无法拆分的工作区更新时，保留当前内容，把整段精简建议降为提示。

### 笔记和用户决定

笔记分决定和下一步，保存内容、时间、作者、记录时的工作区状态。决定可带目标、用户来源和适用范围。

目标可以是需求、方案、检查问题或验证记录。用户要求暂不检查时，决定指向当前任务，并记录仅本轮或整个任务的期限；有效期间跳过相应检查，在报告中注明用户决定。重跑决定指向一次验证，派生出一条仅供下一次相同验证使用的授权；用后标记已使用。普通的解释性笔记不会自动豁免拦截。记录成为有效用户决定或重跑授权时，更新对应的授权修订。

### 检查和问题

检查记录保存任务编号、快照、需求修订、方案修订、编辑记录修订、规则版本、有效分析设置和工具能力标识。静态、动态结果分开保存，注明完成、部分完成、失败或已过期。只有内容或判定依据实际变化才增加对应输入修订；相同内容的观察、hook 活动时间、摘要、检查输出和普通笔记不改变检查输入。

每处问题保存稳定编号、规则、档位、逻辑位置、事实、建议、证据来源、处理状态及拦截过的 session。问题事实没变时沿用编号，移动位置不会重置拦截次数。已解决的问题再次引入时新增发生记录。

检查结束前重新核对输入版本。变化后保存为历史结果，不用于当前拦截。缺失工具、超时和出错的部分可以在环境修复或主动刷新后重试，不能缓存成永久的放行结论。

### session、hook 和验证

session 保存 Agent、session 编号、工作区、开始及最近活动时间、上次摘要采用的输入版本。hook 活动保存事件种类、时间、session、轮次、处理状态，供接入诊断和评估核对 SessionStart、Stop 等事件。

验证记录保存编号、工具调用编号、session、轮次、实际目录、解析后的命令及参数、显示原文、是否混有其他命令、输入与环境标识、开始结束时间、结果和退出码。正在运行、通过、失败、中断、未知分别记录。环境标识只保存比较用摘要，不保存凭据。

被拦截而未运行的命令记为拦截事件，不增加实际验证次数。后续结果只有可核对时才补写；拿不到的保留未知。

## MCP 工具

| 工具 | 参数 | 作用和返回 |
| --- | --- | --- |
| `task_get` | `task_id` 可选 | 当前或指定任务的记录、有效设置、版本、工作区更新和最新检查 |
| `task_start` | 新任务用 `title`；恢复用 `task_id`；可选 `start_message_id`、`workflow` | 暂停原任务，开始、恢复或重新打开目标任务；返回任务和恢复摘要 |
| `requirement_save` | `id` 可选、`content`、`quote`、`source_id`、`acceptance`、`status`、`implemented_by`、更新时的 `base_revision` | 保存需求新修订，返回有效来源、位置及需补充的说明 |
| `note_add` | `kind`、`text`；可选 `target`、`quote`、`source_id` | 记录决定或下一步；核对重跑等决定的目标和来源 |
| `check_run` | `depth` 为 `static` 或 `tests`，可选 `refresh` | 检查固定状态；返回结果、输入版本和完成情况 |
| `task_finish` | `outcome` 默认为 `complete`，用户放弃时为 `cancel` | complete 保存待交付请求并返回已有结果；cancel 保存中止及原因 |
| `plan_save` | `content`、`files`、`entries`、`deps`、`base_revision` | 保存完整方案及变更摘要，返回版本和路径 |
| `plan_confirm` | `version`、`source_id`、`quote` | 核对版本、消息来源和授权时间，返回有效与待确认范围 |

`implemented_by` 每项包含 `at`、可选的 `quote`、`source_id`、`purpose` 和变更类型。传入时替换这一版的位置列表，历史修订保留；不传时沿用原列表。位置未能对应时保留待更新项和原因。

`files` 每项包含 `path`、`change` 和 `note`，以 `/` 结尾表示目录范围。`entries` 每项包含 `at` 和 `note`；`deps` 每项包含 `module` 和 `reason`。空项传空列表。

更新需求或方案时采用 `base_revision` 核对，发生冲突返回最新版本，由 Agent 合并。各工具的幂等重试以 session、工具调用编号和目标版本识别，重复到达不重复开始任务或追加同版方案。

`task_finish` 不运行耗时测试，不立即清掉当前任务。Stop 使用本轮保存的交付任务处理检查和完成；首次反馈后仍保留本轮请求；输入未变时再次 Stop 可直接完成报告。中途有新编辑、需求或授权变化时，请求过期，任务回到进行中。Agent 申请完成前更新需求状态；未完成或已撤销的需求分别列入报告。

全自动任务调用方案工具时，返回当前模式和有效需求，不新增审批。用户明确改变工作模式时，用 `task_start` 指定当前任务和新模式，保留已有内容。

## 保留期限

- 进行中、待交付和暂停任务的记录、起点及恢复快照保留至任务结束。
- 完成或中止后，任务记录、方案和需要回读的快照继续保留三十天，便于重新打开和查看问题证据。
- session、hook 和验证记录保留三十天；仍被活跃任务引用的记录随任务保留。
- 超期时一并清理记录、方案文件和 TaskBelay 自己的快照引用。

存储和清理实现见 [系统架构](product-architecture.md)。
