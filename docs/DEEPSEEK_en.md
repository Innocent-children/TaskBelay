# deepseek Host usage

[中文](DEEPSEEK.md) | [English](DEEPSEEK_en.md)

Install the public manager with npm install -g taskbelay@latest and taskbelay install --host deepseek. The engineering contract is in source builds; published packages/stable records are unchanged. From the repository run node scripts/taskbelay-local.mjs install --host deepseek --yes. Preserve old data and choose a separate explicit TASKBELAY_DATA_DIR. Node.js >=24 is required; source builds need Go >=1.26 and pnpm >=11 <12.

Restart the selected DSH profile; the adapter validates the current MCP namespace and preserves native permissions.

Invoke the TaskBelay Skill with the outcome and necessary restrictions. The agent continues under existing authority; implementation and check-method changes do not require repeat approval. Actual changes to user outcomes or restrictions need a new user decision. Keep the selected workspace. Tools return current summaries with details on demand. Core execution is distinct from claims and human observations; after interruption read the original run before repeating effects. Optional workspace helpers retain actual authorization_ref and return current repositories; relocation is unsupported.

Use the unified manager with --host deepseek for status/doctor/update/remove; ordinary removal retains Task data. Ending tasks grants no Git/publication/cleanup authority. See [package guide](../packages/deepseek/README.md), [commands](COMMANDS_en.md), [verification boundaries](SUPPORT-MATRIX_en.md). Adapter tests are not real Host-session validation.
