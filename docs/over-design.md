# 过度设计判定

过度设计是本次改动中可以撤回或简化、又不影响当前需求和既有行为的部分。TaskBelay 用五类信号找出候选：与需求无关的改动、未经要求的对外新增项、背后没有变化的间接层、重复实现，以及没人使用的代码；再用撤回试验确认能否撤回。代码行数、接口数和实现个数都不单独构成结论。

变更簇、需求相关区、验收依据、分组检验、合并信号和问题标识见 [算法核心](algorithm.md)，单元、新词和仓库统计见 [输入与执行协议](languages.md)。

## 1. 判断对象

变更簇的来源分为逐行核对过的 Agent 编辑、命令写入和工作区更新。命令写入依据同一 HEAD 和分支上的命令前后观察，无法区分命令期间用户的并发保存。含命令写入的簇可以核对用途并给出精简建议，不拦截，也不参加撤回试验。完全来自工作区更新或混有工作区更新的簇保留当前内容，只报告现状。用户明确要求保留的对象，按该决定的适用范围排除，其他对象照常分析。

## 2. 与需求无关的改动

- **缺少归属**：行为改动的变更簇不在任何需求相关区内。报告给出它到各相关区的最强路径，例如“只经由常见词 `Info` 与 R1 相连”。
- **影响面**：改动了起点已有单元的行为时，按该单元在起点中被引用的次数估计影响面，并将其计入撤回收益。改动共享代码比改动新代码更值得核对。
- 变更簇的全部文件已登记为有效需求的实现位置时，不再仅凭相关区未覆盖提示缺少归属。登记不证明实现必要，入口新增、间接层、重复实现和测试检查仍照常进行；混合了未登记文件的变更簇不能整体豁免。
- 需求原话或内容里点名了某个文件时，含这个文件的变更簇直接对应这条需求。按完整路径或带扩展名的完整文件名匹配，例如 `cat.go.bak` 不会豁免 `cat.go`。二进制文件不参与缺少归属提示。
- **噪声**：只改空白、注释或一致改名的变更簇，在原话、需求内容和方案中都找不到对应要求时，列为可以直接撤回的噪声。

## 3. 对外新增项

实现需求时额外增加的功能，例如 CSV 导出里多出的 `--delimiter`，与需求代码联系紧密，也会落在需求相关区内。因此，还要单独检查对外新增了哪些内容：

| 种类 | 识别方式 |
| --- | --- |
| 新文件 | 新增的文档、脚本、示例和配置文件。新文件声明的名字被本次改动的其他代码用到，或者被它们按文件名引用时，它是实现的一部分，不算对外新增项 |
| 注册式调用 | 同一个调用的实参中同时有短键字面量和自然语言句子，如 `("delimiter", ",", "field delimiter")`；参数、配置项、路由和指标的注册多采用这种形式 |
| 入口形状的字面量 | 形如 `--x`、`/path`、`UPPER_SNAKE` 的新字面量。只在含函数声明的代码文件里识别：文档里提到的名字是说明文字，测试里的字面量是测试数据 |
| 配置键 | 配置文件版面树中新增的键 |
| 依赖 | 清单文件中新增的、含名字和版本号的单元 |
| 接口清单差异 | 见下文的探针 |

**探针。** Agent 运行过输出接口清单的命令后，TaskBelay 可以在起点快照和当前快照的副本中分别运行同一命令，再比较输出，确认新增了哪些参数和子命令。接口清单的识别特征是：输出中显著集中地出现 `--x`、路由词，或反复以两列展示短键与说明，例如 help、路由列表、schema 导出。探针只在动态检查开启时运行。

注册形状只比较同一次调用中独立的字面量实参，不把嵌套表达式、函数内不同调用或整段反馈文案拼成注册证据；键至少包含字母或数字，单独标点不能成为入口名。

各种识别方式的可靠程度不同。新文件、清单中的依赖和探针结果直接来自文件内容或命令输出，属于可靠的识别方式。注册式调用、入口形状的字面量和按版面识别的配置键则只按形式识别：日志调用同样可能包含“短键 + 自然语言句子”，内部常量文件也可能符合配置的键值形状。因此，这三类只能先列为候选，经探针确认后才视为可靠的识别结果。

### 需求对应关系

将对外新增项的名字和取值按驼峰、下划线和连字符拆成子词并转成小写，再与以下来源比对。名字中的全部子词都能在来源中找到，或者取值能在来源中找到，才算匹配。说明文字是 Agent 和代码一起写出的，不参与比对。

| 需求对应关系 | 来源 | 结果 |
| --- | --- | --- |
| 原话对应 | 名字或取值与用户原话，或已确认方案中的入口和依赖匹配 | 正常 |
| Agent 说明 | 登记为某条需求的实现位置（`flag:`、`cmd:`、`env:`、`route:`、`config:`、`dep:` 或文件路径），见 [任务和需求](requirements.md#实现位置) | 不拦截；在交付报告的“由 Agent 说明对应需求的新增”中列出对应需求、登记位置、用途说明和已有引用，不再要求重复登记 |
| 没有对应说明 | 不符合以上两种情况 | 识别方式可靠时可以拦截一次 |

例如原话是“给 export 命令加一个导出 CSV 的选项”：`--format` 的取值 `csv` 出现在原话中，属于“原话对应”；`--delimiter` 的名字和取值 `,` 都无法匹配，即使说明文字写成 “CSV field delimiter”，仍属于“没有对应说明”；`--csv-delimiter` 中的 `delimiter` 在原话里找不到，同样属于“没有对应说明”。

没有对应说明的项，同时满足以下条件时拦截一次：识别方式可靠；全部来自 Agent 编辑。Agent 可以撤回，也可以把它登记为某条需求的实现位置并引用原话；登记后，需求对应关系记为“Agent 说明”。既不撤回也不登记的项，列入交付报告的“未经要求的新增”，用户能直接看到。没有对应说明、但只按形状识别且尚未经探针确认的项，只给出建议。半自动模式下，超出有效方案的入口和依赖另由 S2 拦截，见 [半自动模式](semi-auto.md)。

“Agent 说明”只表示 Agent 已登记这处实现与需求的关系，不能据此确认实现有必要，也不能视为用户授权。反馈展示匹配位置的用途和引用；未填写的用途或引用如实标明，不借用其他位置的说明，也不要求重新登记。静态检查、编辑前提示和动态探针确认后的反馈遵循同一规则。原话对应的项继续按现有规则正常处理，没有对应说明的项继续提示撤回或登记；本项改进不改变识别和拦截条件。

新增配置键的提示展示识别到的取值片段，要求核对何时需要切换取值，以及使用固定行为会失去什么功能。已有需求精确登记了声明或测试位置时，交付检查在相应候选旁展示登记的用途和出处，供 Agent 核对实际行为。

没有有效需求时，编辑前提示沿用交付检查的原话回退范围，包括历史记录引用的任务起点前消息；有有效需求时，只读取判定所需的最新需求与当前位置。

只有探针确认后才识别出的已登记命令，也列入完整动态报告，仍只作提示，并遵循用户保留决定。摘要按既有条数和长度预算选择、裁剪内容，不保证展示每项完整说明；完整依据可通过 `task_get` 读取检查记录。

### 编辑前核对新增文件

可完整核对的编辑请求在写入前复用已有新文件识别。对于未与原话或有效方案直接匹配、也未被现有规则识别为其他代码所引用的新文件，反馈展示具体文件和需求对应关系，提示核对谁使用它、它承担什么当前需求、现有文件能否承接，以及单独维护这份文件的成本。没有识别到引用，不能证明文件没有使用者或独立用途；文档、脚本、示例和配置也可能是必要交付。确认多余后再省去，无法确认时保留必要文件，不因此补测试。

已有 Agent 登记继续展示用途和引用，无需重复登记；登记仍不代表必要性或用户授权。原话或有效方案直接对应、同批代码已引用的文件沿用原有略过规则。预览以目标文件的实际当前内容为基线，当前已存在的文件不会重新作为新文件提示；不补读其他文件或查找外部使用者。修改后检查的新文件识别、需求匹配和拦截条件保持原行为。

提醒只作编辑前附加上下文，不拒绝普通编辑、不要求逐项解释，不启动动态检查。索引未就绪、整份请求含删除或无法完整核对的目标，以及分析失败或时间不足时，沿用现有预览略过规则；编辑证据与过期保护先行处理。

## 4. 背后没有变化的间接层

变化数只描述当前仓库可见的结构，不证明间接层没有用途。反馈应区分抽象、参数、转发与旧名兼容：抽象先核对隔离的依赖或变化；参数先核对可见调用是否完整，以及固定实参是否有副作用；转发先核对是否承担入口约定；旧名先核对外部调用和兼容承诺。只有相应行为可以保留时，才建议具体的内联或删除步骤，不把参数取值写成可替换的被调函数。

参数候选只针对新增或首行发生变化的单元；只改函数体不重新建议删除既有参数。相同变量名或表达式不代表运行时取值相同，只有按已有词法约定识别为字面量（含负数）的实参才参与恒定取值建议；变量、调用或无法识别的表达式不据此建议内联。索引调用可能来自当前分析视图之外的文件，实参必须使用调用文件扩展名对应的已学习词法约定；按需查询约定，不加载完整调用文件，并记录约定依赖以支持增量重算。

抽象候选的名字不能是该扩展名下学到的关键字，候选实现的名字要含字母；条件、循环和异常处理不是可以被实现的抽象。声明候选不能位于另一个具备调用声明形状的单元内部，避免把函数内的条件、循环和局部赋值当作函数；转发建议使用相同前提。嵌套函数、闭包和回调因而不在本阶段的声明确认范围内。类等没有参数括号的容器不排除其方法。

参数、闲置函数与重复实现分析先要求可核对的声明形状：首行包含该名字及完整参数括号，后面有实际主体。单独的调用、返回语句、注释及括号中的实参节点不当作函数声明；无法确认的结构不生成这三类建议。这意味着不具备该形状的类型、配置段或特殊声明写法不在这三类建议的确认范围内，不代表它们没有多余内容。与起点同文件位置重叠的旧单元也不作为复用对象，避免把被修改的同一实现当作另外一份代码。

抽象、参数、转发和新旧名字都按词法与版面结构统计“变化数”，找出值得核对的间接层。这个数描述已识别的结构，不能证明实际只有一种实现、参数值不变或转发前后行为相同。

| 对象 | 识别与统计 | 判断边界 |
| --- | --- | --- |
| 抽象 | 成员只有首行、没有主体（或主体只有一个词）的单元；某个已有定义的名字，分别与各成员名在单元首行或其外层首行中共同出现，计为一个候选实现 | 按成员名共现识别，不解析类型关系；候选实现数不等于已经确认的实际实现数 |
| 参数 | 找到新名字后紧跟括号的位置，用括号配对和顶层逗号分出实参，统计已识别同名调用中该位置的不同实参文本数 | 同名调用未必属于同一函数；相同变量名或表达式文本不证明运行时取值固定 |
| 转发 | 单元主体的标识符序列是“一个被调名 + 首行参数按原顺序”，并符合调用形状，变化数为 1 | 不核对运算符、字面量、求值过程和副作用，不能据此确认可以直接替换调用 |
| 新旧名字 | 名字在起点存在，当前符合转发形状；沿用转发的变化数，并展示该名字在起点出现于多少个单元 | 名字曾经存在不证明它承担公开兼容承诺，仓库内引用也不能代表全部外部调用方 |

用新增的单元数、行数和新词数衡量间接层的代价。变化数和代价都作为信号参与合并，不单独用于设定判定阈值。变化数为 1 时，反馈先展示对象位置、实际统计到的结构及其判断边界，再说明它与需求相关区的关系。落在某条需求的相关区内，只说明分析找到了词汇关联，不证明这层间接有必要；未知或没有找到关联时，按实际状态分别说明。

建议按对象分别给出核对条件和成立后的动作：

- **抽象**：核对是否需要隔离依赖或实际变化。确认没有这类用途、类型关系也允许替换时，再将引用改为具体实现类型并删除抽象定义。
- **参数**：核对已识别同名调用是否属于同一函数、对应取值是否确实固定，以及是否需要保留对外参数。条件成立时，将固定值移入函数，删除对应形参和各调用处的实参；保留函数及其其他行为。
- **转发**：核对运算符、字面量、求值过程和副作用，以及这层函数是否承担必要职责。确认直接调用保持原行为且无需保留这一层时，再替换调用并删除转发单元。
- **新旧名字**：先核对内部引用和外部兼容约定。确认不需要保留旧名且替换调用保持原行为时，再迁移引用并删除旧名转发。

反馈只展示当前识别结果能定位的引用或调用形状位置。参数分析展示去重后的位置总数和一个按路径排序的位置示例，避免长位置列表使整条建议超出反馈预算；这些位置不是精确调用次数，仍须核对它们是否确为调用、是否属于同一函数。不能可靠定位时，不声称已经找齐调用方，也不编造替换清单。全部来自 Agent 编辑的对象才给出上述精简动作；其他对象只报告结构事实并保留当前内容。这里改进的是静态候选反馈，不增加语义判定或新的拦截条件，动态撤回仍遵循第 6 节。

起点中同类间接层里变化数为 1 的比例也是一项信号：项目本来就普遍采用单实现接口时，这类建议的可信度相应降低。如果文件中的调用很少采用“名字(参数)”的写法，用于计算结构置信度的调用写法比例就很低，此时参数分析的结论为未知。

新旧名字的调用方不一定都在工作区里；无法确认外部兼容约定时，保留旧名，只提示核对。

### 编辑前核对参数用途

可完整核对的编辑请求在写入前复用已有声明、同名调用和字面量识别，只对新增或首行发生变化的函数形状单元核对参数用途。调用证据仅来自本批目标的拟写入内容；不查询索引中的旧调用、不补读其他调用文件，也不纳入为相近测试比较补齐的参照文件。已识别的文档、配置、依赖清单及测试声明不作为参数候选。当前内容中首行未变的声明，不因只改函数体或调用而重新提示。

某个参数位置在这些调用形状中只有一种字面量写法时，反馈展示参数位置、字面量片段及已识别位置，明确这不代表调用范围完整、同名调用属于该声明或运行值已经确认固定。没有可用调用、存在非字面量或不同字面量时，不给出该位置的固定写法建议；调用写法置信度不足时沿用未知规则。Agent 应核对参数是否需要由调用方提供、入口和兼容约定、实际调用范围及求值行为；确认可以保留这些行为后，才考虑把固定值移入实现，省去本次拟编辑的形参和对应实参。依据不足时保留必要参数，不因此补测试。

预览以目标文件的实际当前内容为比较基线，沿用已发布的词法约定、声明与嵌套节点排除规则，不增加语言规则或完整调用解析。提醒只作附加上下文，不拒绝普通编辑、不要求逐项解释、不启动动态检查，也不授权覆盖或撤回已有用户修改。索引未就绪、整份请求含删除或无法完整核对的目标，以及分析失败或时间不足时，沿用现有略过规则；编辑证据与过期保护先行处理。修改后检查的调用查询、反馈和拦截条件保持原行为。

### 编辑前核对抽象用途

可完整核对的编辑请求在写入前复用已有抽象形状识别，展示本次拟改动中抽象声明的位置与成员名字。预览只比较目标文件的实际当前内容与拟写入内容，未改动的既有抽象不重复提示。已识别的文档、配置、依赖清单及测试不参与抽象预览；对象自身不能符合函数声明形状，避免把函数内的短调用当作抽象成员。抽象形状中的每个成员须在首行有对应的标识符名字，首行含字符串或短键文字值时不作为抽象成员，避免把导入列表中的字符串及其别名当作成员声明；该规则也用于修改后检查的结构统计。成员只有首行、没有主体或主体只有一个词，只能说明符合抽象形状，不能确认类型关系，也不能证明这层抽象多余。

反馈提示核对它隔离了什么实际依赖或变化、现有类型和调用约定是否需要这一层，以及直接使用具体实现会失去什么行为。依据不足时保留必要抽象，不因此补测试。预览从拟写入内容计算结构，沿用已发布的词法约定、关键字和嵌套声明排除规则，不查询索引旧结构、跨文件成员或实现，不统计实现数量；实现候选统计仍由修改后检查完成。提醒只作附加上下文，不拒绝普通编辑，不要求逐项解释。索引未就绪、请求含删除或无法完整预览，以及分析来不及时，沿用现有略过规则。

### 编辑前核对转发包装

可完整核对的编辑请求在写入前复用转发形状识别，只比较目标文件的实际当前内容与拟写入内容，提示本次改动涉及的包装声明及被调名字。未改动的既有包装不重复提示。反馈说明标识符顺序和调用形状不能证明行为等价，提示核对运算符、字面量、求值过程、副作用、独立职责、入口与兼容约定；确认可以保持这些行为后，才考虑直接调用。

预览从拟写入内容计算声明结构，沿用已发布的词法约定，不使用索引中的旧声明结构，不补读调用链或全仓扫描。抽象和参数分别按各自的预览规则核对用途；旧名的独立分类仍留在修改后检查，预览对全部转发包装都提示核对入口和兼容要求，不据名字是否出现过判定兼容承诺。无法识别的声明和嵌套函数沿用原有排除规则。

提醒只作为附加上下文，不拒绝普通编辑，不要求逐项解释，不因此补测试或运行动态检查。整份请求含删除或无法完整核对的目标、索引未就绪、分析失败或时间不足时，沿用现有预览略过规则，编辑证据与过期保护先行处理。建议只针对拟编辑内容，不授权覆盖或撤回已有用户修改。

## 5. 重复实现与没人使用的代码

没有词序列的单元不生成重复候选；LSH 同桶只是检索结果，实际相似度为零时也不发布建议。非零相似度仍须结合用途、输入输出、副作用和依赖核对，不能直接视为行为相同。

相似内容索引和无关单元的相似度分布只保存、抽样上述可核对声明的词序列，不为不会参与重复检查的版面节点计算签名或写入 LSH 桶；其他检查需要的单元和词汇索引继续保留。声明资格随文件学习摘要保存和更新，增量刷新从摘要筛选抽样对象，不为筛选逐个加载全仓库完整单元。

编辑前预览保留具体复用对象和核对建议，并明确只针对本次拟编辑内容；尚无后置编辑证明不等于已有用户修改，预览建议也不授权覆盖已有用户内容。实际交付检查仍按可核对的编辑来源保护工作区更新。

编辑前的相似候选仍由已发布的起点索引检索。给出复用建议前，只读取候选所在文件，核对当前内容和文件模式仍与索引一致；同一文件在这次预览中只核对一次。参照文件已修改、删除、移动或模式变化时，略过该文件的旧候选，其他有效候选继续参与。整份文件的内容变化也会使其中未改动的声明暂时略过，不扫描全仓库寻找替代参照。

参照位于同批编辑的目标文件时，直接使用已读取的当前与拟写入内容；声明须在两份内容中都保留索引记录的位置、范围和完整词流，并仍符合声明形状。声明被改动、移位或删除时，不按旧位置建议复用；同批保留不变的声明仍可参照。核对失败、取消或时间不足时沿用预览略过规则，不拒绝普通编辑。核对只说明参照在读取时仍有效，不能证明两处行为等价，也不能保证提示后文件不会再次变化。相似度计算和修改后检查保持原行为。

**重复实现。** 先规整新单元的词序列（保留标识符，将字面量换成类别），再取 k-gram，用 MinHash 生成签名，最后用 LSH 分桶。b 个桶、每桶 r 行时，相似度为 s 的两个单元进入同一个桶的概率是 `1 − (1 − s^r)^b`，查询的期望时间为常数。计算同桶候选之间的实际相似度，再与仓库中无关单元的相似度分布比较。将相似度和比较结果作为信号，与其他信号合并；这些信号的权重由校准结果决定。提示写明可以复用的已有单元及位置。编辑工具实际写入前就做这项检查，Agent 提出新代码时即可收到提醒。

**没人使用的代码。** 如果一个新词在定义单元以外，只在测试中出现或完全没有出现，而且不符合 [约定入口](languages.md) 的模式，就判为没人使用。字符串和配置文件中出现同名也算使用，以识别通过名字调用的情况。

## 6. 撤回试验

前面几节的信号都只说明关联。要判断一处改动是否需要，唯一能提供因果依据的办法是把它撤回，再看验收依据中列出的用例和命令是否仍然通过。PIT 的 Descartes 引擎采用同一思路：把整个方法体换成直接返回，找出被测试执行、却没有检查执行结果的方法。这里撤回的是本次改动，不需要知道函数的返回类型，因此与语言无关。

- **前提**：动态检查已开启，或本次请求了动态检查。每次试验都运行 [验收依据](algorithm.md) 中列出的全部用例和检查命令。
- **候选**：取前几节标出的、全部来自 Agent 编辑的变更簇，连同依赖它们的簇。某个簇位于一条需求的相关区内时，这条需求必须有自己的验收依据（实现前登记或用户点名），否则不将它列为候选。这是因为起点已有的测试可能仍然通过，从而得出整个新功能都可以撤回的错误结论。防御性代码不作为候选，识别条件是：它是当前单元内的短分支，主体以本仓库的返回或抛出写法开头，且条件中的变量来自同一单元前面的调用结果。
- **搜索**：先在副本中撤回全部候选，再运行一次验收依据中的全部用例和命令；通过时，可一次确认这组候选全部可以撤回。失败时，按 [分组检验](algorithm.md) 将候选二分。需要保留的簇有 d 个时约需 `d·log₂(n/d) + O(d)` 次运行，d 接近 n 时接近逐个运行。
- **确认**：将最终的撤回集合整体应用到副本，再运行一次验收依据中的全部用例和命令；失败时，按可信度把候选逐个加入撤回集合，以最后一次通过的集合为准，见 [分组检验](algorithm.md)。
- **拦截**：确认可以撤回、不在任何需求相关区内、改动的单元也没有登记为任何需求的实现位置的变更簇，交付时拦截一次，附撤回补丁。Agent 可以撤回，也可以把它登记为某条需求的实现位置。在相关区内的只作建议：它可能是需求的一部分，只是验收依据没有覆盖到。
- **产出**：一份确认过的撤回补丁。Agent 原样应用后，工作区内容与确认运行时的副本一致，验证记录中已有这份内容的通过结果。之后请求运行同一验证时，按 [过度测试判定](over-testing.md) 直接复用结果，不需要补跑。

撤回试验只说明“撤回后，验收依据中列出的用例和命令仍然通过”。这些用例和命令没有覆盖的行为，不能由此判断，这时结论只作提示。

## 7. 反馈

每项反馈说明已知事实、需求联系、判断成立的条件和下一步动作，排成三行：对象和类别、事实、动作。拦截排在最前，可以直接动手的建议其次。只报告现状的提示没有可执行的动作，限量展示时只给出数量；无法判断的部分只给数量和少量示例，完整清单在检查记录里。“包含受撤回保护的分支”这句提醒只附在整簇的撤回建议上，不附在针对单个函数、参数或新增项的建议上。需求相关区未知时记录分析缺口，不再逐簇生成没有具体精简依据的“无关改动”建议；其他有独立依据的候选照常分析。静态结构相似不能证明可删除。涉及工作区更新的候选只报告现状，明确保留当前内容，不给出撤回或合并指令。

### 防御处理的核对

防御性短分支继续排除在撤回试验之外。检查有改动的条件分支时，先核对它是否直接判断上一行调用赋值的左值。这里的调用须有配平的圆括号参数，并位于赋值右侧的最外层；单独的下标、类型参数及嵌在下标或实参中的调用不算这份赋值的结果调用。对象成员访问中的同名词也不算直接判断该左值，避免把缓存读取及对象成员比较当作恢复证据。条件可以带比较或取反符号，也可以在除去关键字后只引用该左值，如 `if not ok:`。引入迭代变量的循环不按这种条件处理。再检查分支内是否新增了同名调用或另一项调用。已学到的返回写法中，仅将不同调用的结果作为返回值时，不据此提示新增恢复操作。报告给出两处位置，提示核对重试条件或失败结果是否变化。符合此形状的分支所在簇也受撤回保护。Agent 还可以直接指出其他恢复措施或重复校验，按[用途核对](algorithm.md#用途核对)引用实际改动。Agent 填写的类别本身不改变撤回资格。

可完整核对的编辑请求在写入前也复用上述识别，只比较目标文件的实际当前内容与拟写入内容，提示本次改动涉及的分支调用，不重新提示未改动的既有调用。反馈展示上游赋值、条件使用的同名值和分支调用的位置，并明确这些结构不能确认这是错误路径，也不能证明恢复操作多余；Agent 应核对触发条件、处理职责和调用对结果的影响，保留必要错误传递和资源处理。提醒只通过编辑前附加上下文提供，不拒绝普通编辑、不生成动态运行结论，也不因此要求补测试。

一次编辑反馈中，展示文字完全相同的提示只保留一次，再计算反馈条数和长度预算。同一行两次同名调用可能得到相同文字；位置相同但事实或建议不同的提示仍分别保留，不把去重用于判定代码行为等价。

这项提醒只使用已发布索引中的约定与本次目标内容，不补读调用链或扫描全仓库；已识别的测试单元沿用原有排除规则。整份请求含删除或无法完整核对的目标、索引未就绪、分析失败或时间不足时，沿用现有预览略过规则，编辑证据和过期编辑保护先行处理。无法识别的结构仍留给修改后核对；没有提示不表示不存在多余恢复操作。

Agent 核对候选的用途时，应指出它防范的情况、当前需求或调用约定的依据，以及应由哪一层处理。外部输入校验、实际调用失败、正常并发、限流和幂等要求应保留。默认数据库、Redis 等基础组件正常；未经要求增加备用存储、降级链、补偿队列或恢复机制时，应核对其必要性。内部重复校验只有在所有入口均有有效保证时才建议精简；不得以测试没有触发、分支很短或“更稳健”为依据。不能确认时只说明缺口，不要求因此补测试。

例如，同一次请求按约定允许重试时，说明幂等保证、失败条件和结果，引用当前约定。若现有调用约定要求直接返回失败，自动切换备用服务会改变结果，应说明怎样恢复约定行为。对于校验，应引用外部入口的输入约定，或者给出覆盖内部调用入口的既有保证。只找到一处调用时，不能断言所有入口均受保护。精简建议均以这些业务前提成立为条件。

反馈先写事实，再写具体动作和影响。例：

```text
TaskBelay 交付检查：1 处拦截，2 处建议

[拦截] 对外新增项 --delimiter（cmd/export.go）
  探针：export --help 的输出比起点多了 --delimiter。
  名字和取值在原话和方案中都找不到，也没有登记为任何需求的实现位置；全部来自 Agent 编辑。
  撤回试验：撤回后，R1 的验收用例 TestExportCSV 仍然通过（已确认运行）。
  建议撤回变更簇 c4（参数注册、writeCSV 的 delimiter 参数及其调用处）。
  确需保留时，把 flag:--delimiter 登记为对应需求的实现位置并引用原话，
  它会列入交付报告的“由 Agent 说明对应需求的新增”。
[建议] internal/log/log.go:Info 的改动不在 R1 的相关区内
  只经由常见词 Info 与 R1 相连；该函数在起点被 23 处引用。
[建议] Exporter 按成员名共现识别到 1 个候选实现 csvExporter
  Exporter 位于 R1 的需求相关区；这个词汇关联不证明抽象有必要，成员名共现也未确认类型关系。
  核对它是否需要隔离依赖或实际变化。确认没有这类用途且类型关系允许替换后，
  可将引用改为具体实现类型，再删除 Exporter 定义；当前统计不代表已找齐调用方。
```

同一建议没有新信息时，不重复要求解释。Agent 采纳后，相关的变更簇、相关区和信号按新内容重新计算；采纳确认过的撤回补丁不需要补跑测试。Agent 拒绝时按 [校准](algorithm.md) 记录理由。

## 8. 常见情况

| 场景 | 信号 | 结果 |
| --- | --- | --- |
| CSV 导出多了 `--delimiter`，原话没提，也没登记到需求 | 没有对应说明；探针确认；撤回试验通过 | 拦截一次，附撤回补丁 |
| 同样的 `--delimiter`，动态检查关闭 | 没有对应说明；只按注册式调用的形状识别 | 建议撤回或登记到需求 |
| `--format` 的取值 `csv` 出现在原话中 | 原话对应 | 正常 |
| 原话是中文，Agent 把 `--format` 登记为需求的实现位置 | Agent 说明 | 不拦截，列入“由 Agent 说明对应需求的新增” |
| 顺手改了共享的日志函数 | 不在需求相关区内；影响面大 | 建议，排序靠前 |
| 新接口按成员名共现识别到一个候选实现 | 变化数为 1；按起点比例给先验 | 提示核对类型关系与隔离用途，确认无需保留后再替换引用、删除抽象 |
| 新参数在已识别同名调用处都传 `','` | 实参文本数为 1 | 核对调用归属、固定取值和对外约定；确认后移入固定值，删除对应形参和实参 |
| 新参数在已识别同名调用处都传 `value` | 实参文本数为 1，不证明运行值固定 | 先核对取值，不直接建议删除参数 |
| 函数符合转发的标识符序列和调用形状 | 变化数为 1，不证明求值与副作用相同 | 先核对行为和职责，确认可直接调用后再替换引用、删除转发单元 |
| 新写的函数和已有的 `parseRow` 高度相似 | 近似重复 | 建议复用已有单元 |
| 新函数只在测试里被调用 | 没人使用 | 建议撤回，或说明对应的需求 |
| 新增 `docs/csv.md`，原话没提文档，也没登记到需求 | 新文件没有对应说明 | 拦截一次 |
| 改名后保留旧名转发 | 新旧名字；起点中仍有引用 | 核对内部引用和外部兼容约定；确认无需保留且行为不变后再迁移引用、删除旧名 |
| 用户改过的间接层 | 变更簇混合了工作区更新 | 只报告结构事实，保留当前内容 |
| 用户改过的错误处理 | 变更簇混合了工作区更新 | 保留当前内容，只报告现状 |
| 错误处理分支在验收中没有被执行 | 防御性代码 | 不作为撤回候选 |
| 原话是中文、不含代码词，也没有登记验收 | 需求相关区未知；没有验收依据 | 只作提示 |

## 9. 用户修改与决定

用户修改过的内容按现状分析，混合了工作区更新的变更簇不作为撤回候选。用户明确要求保留某个对象时，记录对应消息和范围，再将该对象从候选中排除。决定可以精确到对外新增项、单元或变更簇，不能因此将整个文件都排除在检查之外。用户之后又要求精简时，采用新的决定。
