# 过度设计判定

TaskBelay 在任务交付时检查累计改动，帮助 Agent 去掉不为本次需求服务的部分。判断分两步：先核对实际变化和需求，再判断某种写法是否值得简化。

任务、需求、工作区更新和编辑记录见 [任务和需求](requirements.md)，各语言的识别方式见 [语言支持](languages.md)。

## 检查输入

- 本次任务的累计 diff，以及其中的新增、修改、删除、移动和改名。
- 当前有效的需求、实现位置、用户决定和方案。
- 可核对的 Agent 编辑及工作区更新。
- 当前源代码中的声明、引用和用法，以及起点代码中的项目惯例。

生成代码、依赖目录和锁文件按 [语言支持](languages.md) 排除；测试代码交给 [过度测试判定](over-testing.md)。

解析缺口只在影响当前累计改动或具体规则判断时计入未完成范围。没有代码改动或只修改文档时，不因未修改源码的解析缺口把本次检查标为未完成。判断新增声明没有使用时，仍须核对引用和隐式入口；判断入口是否新增时，仍须核对起点入口。相关证据不完整就保留未完成状态，不因缩小报告范围而认定通过。测试枚举缺口也只在测试文件有变化、生产代码变化需要核对测试，或需求明确关联已有生产声明时报告。

一处代码如果在用户手动修改后与 Agent 编辑混在一起，检查当前行为，反馈具体可以讨论的地方，不建议撤回整个声明。来源无法核对的改动作为提示。普通停顿时也可以显示提示，交付拦截遵循 [产品需求](product.md)。

## 规则

### D1 没人使用的新增代码（满足条件时拦截）

找出新增声明，检查非测试代码的引用、字符串和配置中的名字，以及语言规定的隐式调用。只有同时满足下面条件才列为拦截：

1. 声明能核对为 Agent 新增，当前没有混入工作区更新。
2. 本次分析完整，声明是内部实现，没有普通引用、按名字调用、框架入口或已知的间接使用。
3. Agent 已申请交付，当前需求和方案没有要求提供这个独立声明。

库的公开 API、插件和无法核对的动态调用作为提示。用户要求新增 API 时，Agent 把 API 列入实现位置，说明与需求的关系即可。

### D2 缺少需求归属的改动（提示）

按 [任务和需求](requirements.md) 建立改动与需求的联系，未能关联的改动交给 Agent 补说明或精简。新增、修改和删除都参与检查；纯删除可以引用编辑前位置。

接线、错误处理和辅助拆分可以服务于同一需求，不要求用户逐项说出。名字引用只是候选关系：连不上需要补证据，连得上也要核对具体改动是否在解决该需求。

### D3 没有说明依据的新增对外入口（满足条件时拦截）

检查新增的命令行参数、子命令、环境变量、HTTP 路由和配置字段。Agent 应把入口列入实现位置，引用本次请求、有效方案或后续用户授权，并说明用途。

能核对为 Agent 新增、语言识别明确、且交付时仍没有需求说明的入口，拦截一次让 Agent 补充或精简。入口属于完成原需求的必要方式时直接关联原请求；增加独立行为时先向用户说明。工作区更新里的入口只报告现状。

例如“支持 CSV 导出”可以对应 `--format`。多出的 `--delimiter` 若没有当前用途，Agent 应去掉；需要增加自定义分隔符行为时，再把新增行为交给用户决定。

### D4 只有一种用法的抽象（提示）

按下表统计新增抽象当前的用法，少于两种时提示；错误类型只要求一处区分。项目惯例和当前用途同时写入反馈。

| 抽象 | 统计方式 |
| --- | --- |
| 接口、trait、protocol、抽象类 | 非测试代码中的具体实现类型 |
| 泛型 | 显式类型实参组合，存在推断用法时注明无法完整计数 |
| 函数类型的参数或字段 | 不同的具名函数或匿名函数 |
| 错误类型、哨兵错误 | 区分该错误的处理位置 |

一种实现不等于没有价值。隔离 I/O、遵循已有接口、约束依赖方向等当前用途，可以由 Agent 结合代码说明。测试替身单独展示，不用于虚增生产实现数。

### D5 值没有变化的参数和字段（提示）

检查未使用的参数、所有可核对调用都传相同常量的参数，以及没有写入或只写入相同常量的字段。

统计包括默认值、隐式零值、构造赋值、后续赋值和复合更新。一个 bool 字段从零值 `false` 变成 `true`，已经有两种状态；不能因显式赋值只有 `true` 就说它不变。别名、反射、解码、继承或间接写入无法确定时，反馈具体未能核对的用法。

接口签名要求的参数、库的公开参数、外部数据映射字段照常保留。Agent 决定内联常量时，要核对调用约定和行为。

### D6 只转发的函数（提示）

新增函数只有一条调用或返回，参数按原顺序原样传递时，指出这一层转发。实现接口、适配第三方、稳定公开入口和统一命名都是可说明的当前用途。

### D7 兼容旧写法（提示）

新增弃用标记、保留旧名的别名，或者旧函数改为转发给新函数时，指出两套写法。Agent 核对发布约定和现有调用方后，选择一并迁移或保留兼容；不假定所有调用方都在工作区里。

### D8 新增直接依赖（提示）

从依赖清单找出新增的直接依赖，列明用途和可采用的已有能力。半自动模式下，新依赖的授权由 S2 检查。

## E1 项目惯例

从起点快照的同种语言代码统计 D4 的同类抽象。至少三个已有样例、其中至少一半具有同样写法时，记为项目惯例，D4 不重复提示。局部模块已经有明确约定时，Agent 可以记录具体位置和依据。

项目惯例说明实现背景，不替代需求归属。用户调整约定后，采用当前有效的决定。

## 用户决定与问题身份

用户明确保留的对象，记录对应消息和范围后从未解决问题中移出。决定可以针对接口、某个参数、某个字段或某组用例，不扩展为整个函数的豁免。

问题身份由任务、规则、逻辑位置和问题事实确定。补笔记、格式化、提交或修复别处，不生成一个新问题；位置移动后继承原身份。问题已解决后再次引入，才作为新的发生记录。

## 结论和参数

| 项目 | 约定 |
| --- | --- |
| D1、D3 | 满足各自完整条件时为拦截，其余为提示 |
| D2、D4、D5、D6、D7、D8 | 提示 |
| D4 用法数量建议 | 两种；错误类型为一处区分 |
| E1 惯例门槛 | 三个已有样例，占同类抽象至少 50% |
| 交付拦截次数 | 同一问题每个 session 一次，每轮最多三次 |

检查结论取当前有效问题的最高档位。按用户决定或项目惯例处理过的地方写进处理记录。未分析的部分单独列出，不生成精简结论。

## 事前提示

只实现当前需求，给新增入口说明用途，优先采用项目已有做法。抽象应有当前用途，改名时核对调用方。用户更新了代码，先读当前内容，再继续修改。反馈要求精简时，只处理自己能核对的编辑。

## 反馈示例

```text
TaskBelay 交付检查：1 处待补说明，2 处精简建议

[D3 拦截] cmd/export.go:--delimiter
  这次 Agent 编辑新增了自定义分隔符入口，还没有对应的需求说明。
  属于当前需求时补上用途和来源；增加独立行为时先与用户讨论。
[D4 提示] internal/export/exporter.go:Exporter
  生产代码只有一种实现。检查能否直接使用 CSV 写出函数。
[D5 提示] writeCSV 的 delimiter 参数
  当前可核对的调用都传 ','，可以考虑内联。
```

## 例子

| 编号 | 场景 | 结果 |
| --- | --- | --- |
| OD-01 | CSV 导出只有一个实现却新增接口 | D4 提示，Agent 核对当前用途 |
| OD-02 | 起点已有八个接口，其中六个是单一实现 | E1 记录惯例，D4 不重复提示 |
| OD-03 | 新参数所有调用都传逗号 | D5 提示 |
| OD-04 | 新入口已关联用户的分隔符请求 | D3 满足，不再拦截 |
| OD-05 | Agent 顺手改日志，未说明与需求的关系 | D2 提示补说明或精简 |
| OD-06 | 推测用户需要进度条并加入口 | D2 提示，D3 要求说明当前需求依据 |
| OD-07 | 交付时有可核对的内部新函数，分析完整且没有使用 | D1 拦截一次 |
| OD-08 | 改名留下旧名转发 | D7 提示核对兼容要求 |
| OD-09 | 新 Service 方法只转发 | D6 提示 |
| OD-10 | 新错误类型没有调用方区分 | D4 提示 |

| OD-12 | 用户无声地重写了 Agent 的错误处理 | 记录工作区更新，保留当前函数，不要求补原话 |
