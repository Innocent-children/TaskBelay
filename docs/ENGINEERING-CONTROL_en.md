# Engineering control design and acceptance

## User problem and available facts

A developer authorizes an outcome and constraints; implementation and verification alternate. The old Core used eleven nodes, file lists, plan confirmations and Host-reported checks. Paths could not identify within-file drift, claims could not prove execution, replanning reset counted usage, downstream records were invalidated broadly and ordinary progress demanded extra user confirmation.

Reliable read-only Git identity, fixed baselines, index/worktree contents and history relations are retained. Core owns authorization, goals, decisions, acceptance and lifetime cost. Repository observation owns code facts; execution owns actual processes, fingerprints, output and recovery receipts; storage owns current Schema, atomic CAS, operation identity, claims and bounded retention. Hosts preserve actual user authority, semantic reasoning and native permissions. CLI, MCP and WebUI share one service. Core never mutates Git or grants permissions.

## Current design rules

- One authorization contains goals, non-goals, interface/data/dependency/design constraints, forbidden paths, checks and the real user-message reference. Existing authorization suffices; ask only for a material authorization change or choice. References are auditable Host testimony, not authenticated conversation proof.
- Programs observe actual Task diffs, forbidden paths, pinned content, dependency manifests, magnitude and workspace identity. Predicted paths and magnitude prompt review. Forbidden paths, pin violations, unauthorized dependency changes and unparseable dependency changes block. Semantic review binds current content and authorization, maps paths to goals and states basis, verdict and uncertainty without model scores.
- Lifecycle is active/done/cancelled. Derived continue/self_correct/verify/stop/ask_user advice is not a workflow cursor. Implementation and checks alternate freely. Completion requires current scope reasoning, applicable passing evidence for every goal and no unresolved execution. Cancellation retains files; terminal Tasks do not reopen.
- Checks retain exact argv, relative cwd, rationale, covered goals, input scope, conditions, selected environment, timeout and retry policy. Whole-repository Git-visible inputs are the default; narrowing requires dependency basis. Explicit directories include ignored files. External or undeclared conditions are not treated as known. Local execution is not a sandbox and obeys native permissions.
- A durable reservation precedes execution. Actual exit, duration, output digests and bounded logs follow it. Agent claims cannot manufacture Core execution; completed user observations are a separate human source. Passing a check and concluding acceptance remain distinct.
- Evidence binds check definition, related requirements/constraints, inputs, selected environment and executable. Only relevant fingerprint changes expire it. Independent revisions and unchanged-content linear commits preserve applicable evidence. Uncertain dependency coverage uses the broader input scope.
- Lifetime runs, execution, Core calls/observation/wall time and separately reported Host time/wait/tokens never reset during revision or compaction. Core wall time overlaps execution and waiting. Every local call, including untasked queries, contributes to global cost. Killed calls retain a separately labeled conservative unknown estimate. Limits do not waive acceptance; increases require real authority. Identical failures require a new hypothesis or changed inputs.
- Recovery reads latest authorization, progress, failed attempts and unresolved operations. Same operation identities recover results without re-executing. A signed local receipt can recover an actual outcome. A dead owner without a receipt remains interrupted_unknown: reconcile effects and obtain new evidence rather than infer passing. Non-repeatable operations require actual user resolution.
- Current snapshots and recent history are bounded; live evidence, pending operations and lifetime cost survive compaction. Terminal purge requires explicit authorization. Old Schema is rejected without migration, reset or data deletion.

## Risks and non-goals

Semantic reasoning and test sufficiency cannot be proven by a model score. Host interception covers only real supported operations. Commands outside Core, remote services and databases are not automatically controlled. Same-user integrity receipts are not an OS security boundary. TaskBelay remains local and does not become a coding model, arbitrary workflow framework, cloud platform, Git publisher or universal sandbox. There is no historical internal compatibility layer.

## Acceptance and comparison

Run actual failing/passing development checks on Windows, same-path scope drift, dependency changes, independent requirement revision, relevant evidence invalidation, response replay and real Core interruption/recovery. Test lifetime cost and compaction, shared CLI/MCP/HTTP contracts and self-contained resources for all four Hosts.

Compare with old main at the same acceptance requirement: executed old workflow tests establish plan-revision-only counting and Host-reported evidence counting. Current native execution establishes provenance, selective applicability and durable uncertainty. Scripts supply semantic judgments; they do not establish native-agent quality, human-time or fee reductions. Report actual overhead and unavailable native Host/macOS checks honestly.

## Assessment before implementation

The concrete result is a delivered authorized change with applicable evidence and recoverable uncertainty. Available local Core/Git/SQLite and adapter APIs allow repeatable checks. Only Core owns Task state; user interaction shows results and necessary decisions rather than stage approvals. Removed mechanisms are replaced completely. Validation judges scope, real evidence, recovery and lifetime cost rather than UI or component counts.

Implemented checks establish that independent revisions retain path/constraint reasoning, restoring checked inputs reuses earlier real passing evidence, intervening failures remain recorded and compaction protects applicable results. Revisions do not erase unanswered user decisions. Core computes semantic scope digests; Host-supplied values cannot stamp validity.
