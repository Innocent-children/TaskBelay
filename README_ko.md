# TaskBelay

[English](README.md) · [简体中文](README_zh-CN.md) · [繁體中文](README_zh-TW.md) · [日本語](README_ja.md) · [한국어](README_ko.md) · [Español](README_es.md) · [Français](README_fr.md) · [Deutsch](README_de.md) · [Português](README_pt-BR.md)

**실제 AI 코딩 작업을 위한 엔지니어링 제어.**

TaskBelay는 Codex, DeepSeek Harness, Claude Code, ZCode와 함께 승인된 목표, 실제 코드 변경, 검증 증거를 저장합니다. 세션을 넘겨 작업할 때 같은 결정을 반복하는 부담을 줄일 수 있습니다. 구현과 기술 판단은 에이전트가 담당합니다.

## 할 수 있는 일

- 목표, 명확한 제외 사항, 인터페이스·데이터·의존성·설계 제약을 개발 중에도 유지합니다. 경로뿐 아니라 파일 내부의 변경을 검토합니다. 범위 이탈은 기존 승인 안에서 수정하며, 승인이나 중요한 선택을 바꿔야 할 때 사용자에게 묻습니다.
- 승인된 로컬 검사를 실행하고 실제 종료 코드, 입력, 환경 조건, 결과를 저장합니다. 에이전트의 주장, 프로세스 실행, 인수 결론은 구분됩니다. 관련 변경으로 증거가 만료되지만 의존 범위의 근거가 있는 독립 검사는 유지할 수 있습니다. 계획 변경은 누적 비용을 초기화하지 않습니다.
- 구현과 검증을 번갈아 수행하고 요구를 수정하며 현재 결과, 실패한 시도, 결과가 불명확한 실행에서 복구합니다. 최근 기록은 제한된 범위에 보관하고 유효한 결과와 누적 비용은 유지합니다.

명령 검증은 호스트의 기본 프로세스 도구에서 `taskbelay check run`을 호출하며 해당 권한과 환경을 사용합니다. WebUI는 작업 검색, 호스트 및 상태 필터, 언어 선택, 사용자 응답과 실행 복구를 지원합니다. 모든 목표에는 통과한 인수 검증이 필요하며 기존 회귀 실패의 수락으로 대체할 수 없습니다. 저장된 상태를 읽을 때는 사용량을 기록하지 않습니다.

기술적 의문은 해결될 때까지 원래 식별자로 보관되며, 내용을 생략해도 사라지지 않습니다. 결과물의 제한 사항은 저장된 판단에서 도출합니다. 호스트 사용량은 미보고, 부분 보고, 보고 완료를 구분하고, 수집하지 못한 값은 알 수 없음으로 표시합니다. 메서드 도움말에는 입력·출력 예시와 오류 처리 방법이 포함되어 소스 코드를 볼 필요가 없습니다. 새 Task 브랜치는 업스트림을 암묵적으로 상속하지 않습니다.

## 시작하기

Node.js >=24와 설치된 코딩 호스트가 필요합니다. 소스 개발에는 Go >=1.26과 pnpm >=11 <12도 필요합니다. 이 소스에는 호환성을 깨는 엔지니어링 업그레이드가 들어 있습니다. 배포된 패키지 버전과 안정 지원 기록은 바뀌지 않았습니다. 새 계약을 사용하려면 현재 소스를 빌드하세요. 이전 데이터는 보존하고 별도의 데이터 디렉터리를 명시적으로 선택합니다. 마이그레이션이나 자동 초기화는 없습니다.

공개 버전 설치:

```sh
npm install -g taskbelay@latest
taskbelay
```

`taskbelay`를 실행하면 업그레이드, Agent에 설치, 점검 및 복구, 제어 센터, 데스크톱 펫, 설치 정보, 플러그인 제거 및 데이터 삭제 메뉴가 열립니다. 방향키로 이동하고 Enter로 확인하며 Space로 여러 항목을 선택합니다. A는 전체 선택, Esc는 선택 내용을 유지한 채 이전 화면으로 돌아갑니다. 업그레이드 화면에는 실행 진입점과 설치된 플러그인의 실제 현재 버전 및 대상 버전이 표시되며, 로컬 개발 설치는 기존 배포 경로를 유지합니다.

플러그인 제거는 데이터를 보존합니다. `delete-data`는 작업 기록, 설정과 펫 환경설정을 삭제하되 플러그인과 등록을 유지하고 원래 경로에 빈 데이터 디렉터리를 준비합니다. `delete-all`은 관리되는 모든 플러그인과 확인된 데이터를 삭제합니다. 두 작업 모두 실행 진입점, 데스크톱 프로그램, 프로젝트 코드와 Agent 대화 기록을 보존합니다. 공유 데이터는 디렉터리별로 확인하며 기본적으로 복구 가능한 위치로 이동합니다. 영구 삭제는 별도 확인이 필요합니다. 실행 중이거나 결과가 불확실한 명령부터 복구하고, ZCode의 모든 창과 세션을 닫았음을 명시적으로 확인해야 합니다. [명령어 문서](docs/COMMANDS_en.md)를 참고하세요. 이 메뉴 변경은 현재 소스에 해당하며 공개 패키지가 새로 출시되었다는 뜻은 아닙니다.

현재 소스를 로컬에서 빌드하고 설치:

```sh
pnpm install --frozen-lockfile --ignore-scripts
node scripts/taskbelay-local.mjs install --host codex --yes
```

해당 [호스트 안내](packages/codex/README.md)에 따라 어댑터를 활성화한 뒤 명확한 범위의 결과를 요청합니다:

```text
TaskBelay로 로그인 실패 요청 제한을 추가하세요. 공개 인증 API와 기존 사용자 데이터를 유지하고 계정 관리는 다시 설계하지 마세요. 관련 기존 테스트를 실행하고 실제 결과를 보고하세요.
```

원하는 결과와 필요한 제한을 설명합니다. 에이전트는 접근 방법을 설명하고 기존 승인 범위에서 작업합니다. 일반적인 구현이나 검사 방법 변경에는 재승인이 필요하지 않습니다. 목표나 명시된 제한을 바꿀 때는 사용자의 실제 결정이 필요합니다. 유효한 통과 결과는 재사용하며 사용량은 계속 기록합니다. 한도는 사용자가 설정한 경우에만 적용합니다. WebUI는 간결한 작업 목록과 상세 내용을 두 열로 표시하며 개요, 검사 기록, 요구 사항 및 사용량 탭을 제공합니다. 출력은 해당 검사 바로 아래에서 펼쳐지고 답변, 실행 복구, 보관을 지원합니다. 기록 업데이트는 저장된 내용을 읽고, 현재 코드 확인은 실제 조건을 다시 관찰합니다. 저장한 Task ID로 원래 작업 공간에서 재개합니다.

에이전트는 디렉터리, 브랜치, 기존 변경 사항을 보여 주고 사용자가 선택했거나 문맥상 명확한 작업 공간을 사용합니다. 위치가 불명확하거나 충돌이 있거나 새로운 작업 공간 작업이 필요할 때만 질문합니다. 브랜치와 워크트리 생성, 업스트림 통합은 선택 사항이며 실제 승인에 따릅니다.

```sh
taskbelay webui start
```

## 한계

구조화된 훅은 지원되는 쓰기 경로를 검사하고 shell 및 외부 편집은 검사 지점에서 관찰합니다. Core가 직접 실행한 검사만 Core 실행 증거를 갖습니다. 선언된 입력과 환경은 ignored 의존성, 데이터베이스, 원격 서비스를 자동 포함하지 않습니다. 의미 판단은 근거를 남기지만 정확성의 증명은 아닙니다. TaskBelay는 샌드박스나 또 다른 코딩 에이전트가 아닙니다.

Core 비용은 실측합니다. 호스트 분석, 대기, token은 보고 값으로 불완전할 수 있습니다. 작은 기계적 작업은 보통 원래 에이전트만 사용하는 편이 단순합니다. 소스 테스트는 기능을 입증하지만 결함률이나 수동 감독 비용 감소를 입증하지 않습니다. 완료해도 파일은 남으며 Git, 배포, 삭제 권한은 추가되지 않습니다.
