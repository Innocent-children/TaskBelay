# 语言无关的输入与执行协议

本文件保留原路径 `languages.md`，定义目标算法的统一输入：任何文件怎样变成词、单元和统计，命令和结果怎样记录，TaskBelay 怎样在副本里运行项目已有的命令。算法不按语言分级，不为任何语言写规则表或 Runner；判断所需的语言知识都从仓库自身统计得到。

当前程序仍包含 `internal/lang`、`internal/codescan` 和 `internal/testrun` 的语言适配实现，已有的 `test.<语言>.*` 设置仍按当前实现解释。本文描述目标设计，不表示这些模块已经替换。

## 内容与改动

所有文件先作为字节内容、路径和版本处理。记录包括工作区身份、文件身份、blob 标识、范围、变更类型和来源。

- 新增和修改定位到当前内容；删除保留编辑前内容和来源。
- 移动和改名优先使用可核对的编辑记录；没有编辑记录时，用 [变更簇](algorithm.md) 的移动检测，能唯一对应才迁移位置。
- 子模块与嵌套仓库记录边界和引用的版本，不展开为普通目录；未观察到的内容不假定不存在。
- 二进制内容不分词，按整体记录变化。

## 统一词法

一个确定有限自动机单遍扫描文件，复杂度 O(字节数)，把文本切成标识符、数字、字符串、符号和空白。字符串再分为两种：

- **短键**：形如标识符、不含空格的字符串，例如 `"delimiter"`。
- **自然语言句子**：含空格、常用词比例高的字符串，例如 `"field delimiter"`。

哪些引号是字符串定界符、哪些记号开启注释，不预先规定，按下文从仓库统计。

## 版面树与单元

用栈做括号配对得到一棵树，按缩进层级得到另一棵树，取与这个文件更一致的那棵：括号配对失败少、缩进与括号层级吻合时用括号树，否则用缩进树。树的节点叫**单元**；在大多数语言里，顶层单元就是函数、类型或配置段。单元的第一行叫**首行**，首行中低频的词是单元的名字。

配置文件同样建立版面树，每一层键是一个单元。

## 从起点学习的约定

以下约定按文件扩展名分组，从起点快照统计，按 blob 标识缓存并累加；起点 tree 变化时只重新统计变化的 blob：

| 约定 | 统计方法 |
| --- | --- |
| 字符串定界符 | 在同一行内大多成对出现的引号字符 |
| 注释记号 | 常出现在行首、其后自然语言词比例高的符号序列 |
| 关键字与名字 | 在单元首行中文档频率很高的词是关键字（如 `func`、`def`、`pub`），低频词是名字 |
| 调用写法 | 标识符后紧跟左括号（含方括号、尖括号）的比例；比例低的文件不做实参分析 |
| 返回与抛出写法 | 单元最后一行最常见的开头词 |
| 测试内容 | 测试词汇、路径模式和运行输出中出现的用例名，见下文 |
| 约定入口 | 起点中定义后再没出现过的名字的模式，见下文 |
| 生成内容、锁文件和清单 | 文件开头说明生成来源的文字；几乎每个单元都含名字、版本号和哈希的文件是锁文件；很多单元含名字和版本号、不含哈希的文件是清单 |
| 依赖目录 | 自带清单和许可证文件的子目录 |

**测试内容。** 运行输出中出现的用例名所在的单元作为初始样本；还没有运行记录时，用路径中含 test、spec 一类词的文件作为初始样本。用带 Dirichlet 先验的对数几率比（Monroe 等，2008）比较样本单元与其余单元的词频，得到断言、mock 和夹具相关的词；再用这些词重新划分测试单元，迭代到划分不再变化。

**约定入口。** 起点中定义后再没出现过的名字，要么是死代码，要么由框架按约定调用。对这些名字的前缀、后缀、首行关键字和所在路径计数；某个模式中“只出现一次”的比例经二项检验显著高于全仓库的平均比例，这个模式就是约定入口，例如 `Test*`、`main`。

## 结构置信度

每个文件有一个结构置信度，由版面树的一致性、该扩展名的统计样本量和调用写法比例组成。置信度作为信号进入 [合并信号](algorithm.md)：结构信息少的文件，相关结论的多余概率更接近先验，不会因为信息少而得出强结论。

## 命令与运行记录

每次命令记录：

| 字段 | 内容 |
| --- | --- |
| 身份 | 程序、参数、实际目录、命令中的环境变量和 shell 写法 |
| 工具身份 | 程序的实际路径，以及它的内容哈希或版本输出 |
| 结果 | 是否启动、退出状态、输出、开始和结束时间 |
| 工作区 | 运行前后的工作区状态 |

复杂命令仍由原 shell 执行，TaskBelay 只记录解析结果，不改写命令。环境摘要只保存比较用的哈希，不保存凭据原文。

命令是不是验证，由行为判断，不用命令名白名单：运行前后工作区不变、结果随代码变化、在编辑之后被反复运行、输出中出现用例名的命令归为验证。记录不足以判断时按普通命令记录，不作重复判断。

## 运行结果

退出状态取自 Agent 提供的结构化结果；拿不到时为未知，不从输出文字猜测。

单条用例的结果从输出解析：用例名来自测试单元；“通过”和“失败”的标记词通过比较退出状态为零和非零的输出学习得到，只在失败输出中出现在用例名附近的词是失败标记。解析不出单条用例时，整条命令作为一个结果。

## 副本中的运行

动态检查由项目设置开启，或通过 `check_run(depth="tests")` 请求。开启后，撤回试验、变异和探针按以下方式运行：

1. **只运行可信命令**：只使用 Agent 在本任务中已经在真实工作区运行成功的验证命令。
2. **写时复制的副本**：从固定快照导出副本，文件系统支持时用写时复制（APFS 的 clonefile、Linux 的 reflink），否则普通复制。
3. **确认命令读的是副本**：先在副本上运行一次，作为当前快照的结果；再对相关文件做一处必然无法构建的哨兵改动。命令仍然通过时，说明它不读这些文件或不在副本中运行，不能作为这些文件的验收依据。结果按命令和文件缓存。
4. **不影响真实工作区**：运行前后核对真实工作区状态；发生变化时停止动态部分并报告。
5. **资源**：默认串行，项目设置声明命令可以独立运行时并行。以较低优先级运行，Agent 开始自己的验证时暂停。
6. **预算**：到期或取消时终止本次启动的进程组，清理副本，保存已完成的确认结果。

涉及数据库、服务、端口等外部状态时沿用项目已有的约定。Agent 自己的日常命令照常在真实工作区运行，TaskBelay 只记录。

## 普适性的验收

把整个仓库中的某个扩展名一致地换成另一个，或把工具名一致地改名，统计按新的扩展名重新分组，命令仍按行为归类，结果应与原来相同（同分时按稳定规则排序）。这检验算法没有语言分支。

不同语言的差异只体现在统计结果和结构置信度上：版面规整、样本多的文件得到更强的结论，结构信息少的文件结论更少。添加新的项目或工具，不需要新增规则。
