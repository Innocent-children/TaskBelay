# TaskBelay

[English](README.md) · [简体中文](README_zh-CN.md) · [繁體中文](README_zh-TW.md) · [日本語](README_ja.md) · [한국어](README_ko.md) · [Español](README_es.md) · [Français](README_fr.md) · [Deutsch](README_de.md) · [Português](README_pt-BR.md)

**実際の AI コーディング作業を支えるエンジニアリング制御。**

TaskBelay は Codex、DeepSeek Harness、Claude Code、ZCode と連携し、許可された目標、実際のコード変更、検証証拠を一緒に保存します。セッションをまたいでも判断の繰り返しを減らせます。実装と技術判断はエージェントが担当します。

## できること

- 目標、対象外の事項、インターフェース・データ・依存関係・設計の制約を開発中も維持します。パスだけでなくファイル内の変更を確認します。範囲の逸脱は既存の許可内で修正し、許可や重要な選択を変更する必要がある場合にユーザーへ確認します。
- 許可されたローカル検証を実行し、実際の終了コード、入力、環境条件、結果を保存します。エージェントの申告、プロセス実行、受入判断を区別します。関連変更で証拠は失効しますが、依存範囲の根拠がある独立した検証は保持できます。計画変更で累計コストはリセットされません。
- 実装と検証を交互に行い、要件を修正し、成果・失敗した試行・結果不明の実行から再開します。最近の履歴は上限内で保持し、有効な結果と累計コストは残します。

コマンド検証はホストのネイティブ実行ツールから `taskbelay check run` を呼び出し、その権限と環境を使います。WebUI はタスク検索、ホスト・状態フィルター、言語選択、ユーザー回答、実行の復旧に対応します。各目標には合格した受け入れ検証が必要で、既存の回帰テスト失敗を受容しても代替できません。保存済み状態の読み取りでは計測データを書き込みません。

技術上の懸念は、解決されるまで元の識別子で保持され、記述を省略しても消えません。成果物の制限事項は保存された判断から導出されます。ホストの使用量は未報告・一部報告・報告済みを区別し、取得できない値は不明と表示します。メソッドのヘルプには入出力例とエラー処理があり、ソースの参照は不要です。新しい Task ブランチは上流を暗黙に継承しません。

## 開始する

Node.js >=24 と導入済みのコーディングホストが必要です。ソース開発には Go >=1.26 と pnpm >=11 <12 も必要です。このソースには互換性を破る工程制御の更新が含まれます。公開済みパッケージと安定版の対応記録は変更されていません。新しい契約を使うにはソースをビルドしてください。旧データは保持し、別のデータディレクトリを明示的に選びます。移行や自動リセットはありません。

公開版のインストール：

```sh
npm install -g taskbelay@latest
taskbelay
```

`taskbelay` を実行すると、更新、Agent へのインストール、診断と修復、コントロールセンター、デスクトップペット、インストール情報、アンインストールとデータ削除を選べます。矢印キーで移動、Enter で確定、Space で複数選択、A で全選択、Esc で選択を保持したまま戻ります。更新画面にはランチャーとインストール済みプラグインの現在および更新先の実際のバージョンが表示され、ローカル開発版の配布経路も維持されます。 すべて最新の場合、更新画面からホームに戻るか再確認できます。V でコンポーネントを1つ選び、そのバージョンを指定します。ローカル配布パッケージの選択はローカルインストール時だけ表示されます。確認をキャンセルすると何も実行されません。正常なインストールでデスクトップアプリのファイルが同じ場合、ペットを停止したり再更新したりしません。

アンインストールはデータを保持します。`delete-data` はタスク記録、設定、ペットの設定を削除し、プラグインと登録を保持して元の場所に空のデータディレクトリを用意します。`delete-all` は管理対象の全プラグインと確認済みデータを削除します。どちらもランチャー、デスクトップアプリ、プロジェクトのコード、Agent の会話履歴を保持します。共有データはディレクトリごとに確認し、既定では復元可能な場所へ移動します。完全削除には別の確認が必要です。実行中または結果不明の処理を先に復旧し、ZCode の全ウィンドウとセッションを閉じたことを明示的に確認してください。[コマンドリファレンス](docs/COMMANDS_en.md)を参照してください。これらは現在のソースの機能であり、公開パッケージの更新を意味しません。

現在のソースをローカルでビルドして導入：

```sh
pnpm install --frozen-lockfile --ignore-scripts
node scripts/taskbelay-local.mjs install --host codex --yes
```

対応する[ホストガイド](packages/codex/README.md)でアダプターを有効化し、範囲の明確な結果を依頼します：

```text
TaskBelay を使ってログイン失敗のレート制限を追加してください。公開認証 API と既存のユーザーデータを維持し、アカウント管理は作り直さないでください。関連する既存テストを実行し、実際の結果を報告してください。
```

期待する結果と必要な制限を伝えます。エージェントは進め方を説明し、既存の許可の範囲で作業します。通常の実装や検証方法の変更に再承認は不要です。目標や明示された制限を変える場合は、ユーザーの実際の判断が必要です。有効な成功結果は再利用し、使用量は継続して記録します。上限はユーザーが設定した場合のみ適用します。WebUI はコンパクトなタスク一覧と詳細の2列構成で、概要・検証記録・要件と使用量のタブを備えます。出力は該当する検証の直下に展開され、回答・実行の復元・アーカイブに対応します。「記録を更新」は保存内容を読み取り、「現在のコードを確認」は実際の条件を再観測します。保存した Task ID で元のワークスペースから再開します。

エージェントはディレクトリ、ブランチ、既存の変更を示し、ユーザーが選んだ、または文脈から明らかな作業場所を使います。場所が不明、競合がある、新しい作業場所の操作が必要な場合だけ確認します。ブランチやワークツリーの作成、上流との統合は任意で、実際の許可に従います。

```sh
taskbelay webui start
```

## 制限

構造化フックは対応する書き込みパスを検査します。shell や外部編集はチェックポイントで観測します。Core が実行した検証だけが Core 実行の証拠になります。宣言した入力と環境は ignored の依存物、データベース、外部サービスを自動的には含みません。意味の判断は根拠を残しますが、正しさの証明ではありません。TaskBelay はサンドボックスでも別のコーディングエージェントでもありません。

Core の負担は実測します。ホストの分析、待機、token は申告値で、不完全な場合があります。小さな機械的作業は通常、元のエージェントだけで十分です。ソーステストは能力を検証しますが、不具合や人の監督コストが減ったことを実証しません。完了後もファイルは残り、Git 操作、公開、削除の権限は追加されません。
